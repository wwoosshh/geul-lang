# 0단계 — 실제 버그에서 무엇이 손실됐나 (docs/17 §7)

종이 시험(0′)은 설계자가 실수를 골랐다. 이 단계는 **공개된 실제 버그**를 정해 둔 규칙으로 모아 무엇이 손실됐는지
분류하고, 글의 문법이 그것을 막는지 잰다. docs/17 의 판정: 목록의 **절반 이상**을 글의 컴파일 오류 또는 "적을 자리
없음"으로 표현할 수 있으면 계속, 아니면 방향을 고친다.

아래 "방법"은 버그를 모으기 전에 적고 커밋했다(2026-10-08). 결과는 그 뒤에 붙인다.

## 방법

### 출처와 질의

마감: 2026-10-01 전에 머지되었거나 닫힌 것. 질의는 `gh search` 로 돌리고, 출처마다 순서대로 내려가며 **포함 조건을
만족하는 처음 10개**를 넣는다(사후 분석은 전부). 건너뛴 후보도 이유와 함께 적는다.

| 출처 | 질의 | 순서 |
|---|---|---|
| Anthropic [사후 분석](https://www.anthropic.com/engineering/a-postmortem-of-three-recent-issues) (2025-09) | 글에 적힌 문제 전부 | 글의 순서 |
| PyTorch (`pytorch/pytorch`) | 닫힌 이슈, 라벨 `module: correctness (silent)` | 생성일 내림차순 |
| vLLM (`vllm-project/vllm`) | 머지된 PR, 제목에 다음 낱말 중 하나: incorrect · wrong · accuracy · NaN · garbage · gibberish · precision · correctness · overflow (질의 아홉의 합집합) | 생성일 내림차순 |
| llama.cpp (`ggml-org/llama.cpp`) | vLLM 과 같은 낱말, 머지된 PR | 생성일 내림차순 |
| FlashAttention (`Dao-AILab/flash-attention`) | 같은 낱말, 머지된 PR 과 닫힌 이슈 | 생성일 내림차순 |

### 포함 조건 (모두 만족)

1. **결과가 틀렸다** — 틀린 값, NaN·Inf, 엉뚱한 출력(쓰레기·반복·다른 언어), 정확도 하락, 또는 계산 중의 잘못된 메모리
   접근. 검사 코드가 낸 예외만 있는 것, 멈춤, 메모리 부족, 성능, 빌드·설치, 문서, API·UI 는 뺀다.
2. **원인이 연산에 있다** — 커널, 연산 구현, 모델의 수식 코드(층·어텐션·샘플링 수식), 양자화·역양자화, 가중치의 배치·형식,
   수치 설정(타입·정밀도 플래그), 컴파일러·코드 생성. 토크나이저, 채팅 틀, 요청 배정·스케줄링 논리, 입출력은 뺀다.
3. **고쳤거나 원인이 밝혀졌다** — 머지된 수정, 또는 원인을 밝힌 이슈(수정 커밋·PR 이 이어진 것). "계획 없음"으로 닫힌 것은 뺀다.

### 모으기와 분류를 나눈다

- **모으기** — 후보를 순서대로 읽고(PR·이슈 본문, 필요하면 diff) 증상·원인·수정을 사실대로 적는다. 모으는 쪽은 글의
  문법이나 이 연구의 가설을 보지 않는다.
- **분류** — 다 모은 뒤 한 번, 아래 기준으로 한다. 애매하면 막지 못한 쪽(통과)으로 센다.

### 분류 기준

**무엇이 손실됐나** — docs/17 §5 의 갈래에 컴파일러 내부를 따로 둔다. 주 갈래 하나, 필요하면 부 갈래 하나.

| 갈래 | 묻는 것 | 예 |
|---|---|---|
| 자리 | 값이 어디에 있고 어디로 가는가 | 축의 이름·순서·배치, 인덱스·보폭·오프셋, 크기의 대응, 경계, 주소 공간 |
| 정체 | 무슨 값인가 | 정밀도·타입, 저장 형식(양자화·영점·묶음), 척도, 종류 |
| 흐름 | 누가 읽고 누가 쓰는가 | 역할(출처·목적지·누적), 겹침, 순서·동기화, 상태의 재사용 |
| 의도 | 무엇을 계산하려는가 | 공식, 경계의 방향, 알고리즘 |
| 컴파일러 내부 | 컴파일러가 의미를 바꿨는가 | 오컴파일, 최적화 재량(합침·순서 바꿈), 근사 |

**글이 막는가** — 근거는 종이 시험의 [가상 문법 v0](../종이시험/README.md) 규칙 1~11 과 docs/17 에 적힌 계획(2단계 의미
층, PTX 계약)뿐이다. 판정하면서 새 규칙을 지어내 막는 것은 세지 않는다.

| 판정 | 뜻 | 판정 비율에 |
|---|---|---|
| 거부 | v0 규칙이나 2단계 의미 층이 그 실수를 컴파일 오류로 만든다 — 규칙 번호를 적는다 | 센다 |
| 자리 없음 | 그 실수를 적을 코드가 v0 표기에 없다 — 인덱스 계산·보폭·크기 인자·묶음 순서 등 | 센다 |
| 계약 | 컴파일러 내부 갈래에서, PTX 계약·비트 대조 같은 단계별 검사가 드러낸다 (주장 A) | 따로 적고, 세지 않는다 |
| 조건부 | 지금 문서에 없는 규칙이 있어야 막는다 | 따로 적고, 세지 않는다 |
| 통과 | 막지 못한다 | — |

**증상** — 다른 연구의 AI 버그(무한 반복, 다른 언어 출력, 논점 상실, 출력 실패)와 잇기 위해 함께 적는다: 조용한 수치
오차·정확도 하락 / NaN·Inf / 엉뚱한 출력(쓰레기·반복·다른 언어) / 출력 실패(잘못된 메모리 접근 등).

**판정** — (거부 + 자리 없음) ÷ 포함된 버그 전체 ≥ 1/2 이면 계속, 아니면 방향을 고친다.

### 미리 적는 한계

- 분류는 한 쪽(이 연구의 AI 에이전트)이 한다. 행마다 링크와 근거를 두어 누구든 다시 볼 수 있게 한다.
- 글의 문법은 아직 가상이다. "막는다"는 종이 위의 판정이다.
- 제목 낱말로 고른 PR 은 제목에 증상을 적은 버그 쪽으로 기운다. 라벨로 고른 PyTorch 가 그것을 조금 덜어 준다.
