## 어떻게 — 손실이 가중치 형식 하나뿐인 까닭

**값.** GGUF 의 블록은 열 하나의 k 32 줄(값 32 개)과 척도 d(f16)다. Q8_0 의 값은 q · d (q 는 8비트 정수), Q4_0 은 (니블 − 8) · d. 커널은 정수를
`으로 짧은실수` 로 바꾸고(정확) 척도(반실수를 정확히 넓힌 것)를 곱한다 — 곱의 가수는 Q4_0 이 15 비트, Q8_0 이 19 비트 이하라 짧은실수
안에서 **정확하다**. F16 은 넓히기 자체가 정확하다. 그래서 커널 안에서 푼 값은 ggml 의 풀기(= 참조 판의 짧은실수 가중치)와 같고, 곱해더하는
순서도 같으니(순서 약속 — 가닥 g 가 k ≡ g (mod 4) 를 오름차순 곱해더하기, ((p₀ + p₂) + (p₁ + p₃)) + 치우침) 로짓이 비트까지 같다(5a).

**배치 (값과는 상관없다).** GGUF 의 블록을 GPU 에 **블록 평면 배치**로 깐다: 칸 (kb, g, n) = 열 n 의 k = 32·kb + g + 4i (i < 8) 여덟 값 — 가닥
g 의 스레드가 맡는 값들이다. 칸 번호 (kb·4 + g)·N + n 이라 워프의 스레드(열)가 붙여 읽는다. Q4_0 은 칸마다 32 비트 낱말 하나(바이트 i' 가
qs[g + 4i'] — 니블의 짝이 ggml 과 같다), Q8_0 은 낱말 둘(평면 둘, 바이트 + 128), F16 은 반실수 여덟(16 바이트 — 넷씩 묶어 읽는다).
척도는 [kb][n]. 세 파일의 1억 2353만 칸 모두 깐 것을 다시 편 값이 ggml 의 풀기와 비트까지 같다(펴보기).

**커널.** 따로 도는 선형 판(줄선형 1 · 4, 깊은줄선형1, 64 × 64 · 32 × 32 타일)은 짧은실수 판과 배치 · 순서 · 끝손질이 같고 가중치만 칸에서
푼다(타일 판은 칸을 레지스터로 한 조각 앞서 읽어 판에 풀어 둔다). 로짓은 낱말표의 형식으로 만든 판(Q4_0 파일은 Q8_0), 임베딩도 같은 표에서
값 하나씩 푼다. 생성 메가커널의 행렬곱은 칸을 두 벌의 레지스터로 번갈아 읽고(한 벌을 풀어 곱해더하는 동안 다음 벌이 온다), 입력 x 를
공유 메모리에 가닥끼리 붙여 두어 여덟 칸을 넷씩 묶어 읽는다.

**백엔드 — 같은 값을 빠른 명령으로.** 2e 의 구간 해석이 `((q >> s) & 15) − 8` 의 범위를 [−8, 7] 로 증명하므로:
- 범위가 |x| < 2²² 로 증명된 정수 → 짧은실수: 실수 12582912(1.5 × 2²³)의 비트에 x 를 더하고 12582912 를 뺀다 — 결과는 x 정확히(느린
  `cvt.rn.f32.s64` 와 비트까지 같다).
- `((w >> s) & 255) − c` · `((w >> s) & 15) − c` (32 비트 w, 상수 s · c): 바이트를 12582912 의 아래 8 비트에 `prmt` 하나로 끼우고
  (12582912 + c) 를 뺀다 — 두 수가 두 배 안이라 뺄셈이 정확하다. 니블은 낱말의 니블을 바이트마다 하나씩 모아(and · shr — 같은 낱말의
  니블끼리 같은 식이라 한 번) 같은 길로.
- 이 둘을 넣고 4단계 2 의 짧은실수 판을 옛 PTX(이 단계 전)와 새 PTX 로 같은 일을 시켜 로짓 1,729만 칸을 견줬다 — 다른 칸 0.
