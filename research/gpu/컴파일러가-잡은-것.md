# 컴파일러가 잡은 것과 놓친 것 — 1~27단계 (주장 A 의 셈)

(2026-10-12) [17장](../../docs/17-연구-의미를-지키는-GPU-컴파일러.md)의 주장 A 는 "의미는 라이브러리 아래, 컴파일러 안에서도
손실되므로 컴파일러여야 한다"이다. 바깥 평가는 이 주장의 정량 근거가 "글 컴파일러가 거부했거나 강제한 사례의 목록"뿐인데,
그 목록이 문서 곳곳에 흩어져 있어 아무도 셀 수 없다고 했다. 이 문서가 그 목록이다. 놓친 것도 같이 센다 — 잡은 것만 세면
근거가 아니라 광고가 된다.

## 무엇을 셌나

- 읽은 것: 17장, `research/gpu/` 의 단계 README(1~13단계), GeulPU 의 `문서/14단계.md` ~ `27단계.md` · `계약.md`, 두 저장소의
  커밋 기록. 행마다 출처를 적었다(줄 번호는 2026-10-12 기준).
- 1~15단계의 GPU 길은 파이썬 참조 앞단 + `글ptx.py`, 16단계부터는 자체 컴파일러 안의 PTX 뒷단(`자체PTX/PTX.gl`)이다.
  둘 다 "글 컴파일러"로 센다.
- 갈래:
  - **R** — 이 프로젝트의 실제 코드를 컴파일 때 거부했다.
  - **E** — 컴파일러가 언제나 지키는 규칙(한 무리의 손실을 만들 수 없게 한다). 잰 효과가 있으면 적는다.
  - **C** — 컴파일러가 넣은 실행 시 검사(오류 칸)가 실제로 켜졌다.
  - **T** — 시험 · 측정 · 손으로만 잡혔다. 컴파일러는 못 잡았다.
  - **S** — 컴파일러나 언어 자신이 낸 조용한 손실.
- 세지 않은 것: 0단계(남의 버그 43 개를 종이 위에서 판정), 종이 시험 0′, 감사 A1~A3(다른 소프트웨어), 드라이버의 동작(KPARAM_INFO
  를 빼면 조용히 틀림), 계약 손실 검토의 규칙 (다), 순수한 최적화 발견(11단계 MOV, 27단계 주소 셈, CI 의 넘침 목록), 사용자가
  글로 쓴 검사(모양 거부, 25b 예산 검사).

**읽는 법.**
- 컴파일 때 실제 코드의 의미 손실을 막은 기록은 적다. 주장 A 의 근거는 대부분 **E**(규칙으로 무리를 막음)와 **C**(오류 칸)다.
  P1 은 측정이 분명한 유일한 E 다.
- 계획한 컴파일 때 의미 층 — 축 · 역할 · 종류 타입, 2d · 3d, 주장 C 의 C1~C3, 읽기 전용 역할 — 은 만들지 않았다(17장 §7 의
  상태 칸이 비어 있다). 그래서 그것이 거부한 실제 코드도 0 이다.
- 놓친 글 코드의 버그 13 가운데 같은 뿌리가 되풀이된다.
  - **안쪽 블록의 가림** 3번(#19 6단계 `M2`, #35 9~14단계 적힌지수의 `e`, #51 22단계 `b0`·`p0`) — 모두 조용했고 17장 · 14단계 ·
    22단계가 "v0 규칙 후보"로 적었다. 명세 4절은 안쪽 블록의 가림을 허락한다.
  - **크기가 타입에 없는 버퍼** 2번(#17 `공유판N` 넘어 쓰기, #34 `조각칸` 넘어 쓰기) — v0 규칙 1 이 막을 자리이고, 그 규칙은
    구현하지 않았다.
