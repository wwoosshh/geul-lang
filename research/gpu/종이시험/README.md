# 종이 시험 — 같은 커널을 CUDA 와 글 서술형으로 (docs/17, 0′단계)

구현하기 전에, 말하는 어법의 문법(역할 조사·축 이름·배분어·의미 꼬리표)이 GPU 커널에서 **의미를 얼마나
가볍게 담고, 실수를 얼마나 컴파일 시점에 막을 수 있는지** 종이 위에서 잰다. 주장 B("글의 문법이어야
한다")의 첫 자료다. 글 쪽은 아래의 **가상 문법 v0** 로 썼다 — 아직 컴파일되지 않는다.

커널 다섯: 소프트맥스, 행렬곱(bf16 입력·fp32 누적), RMS 정규화, 4비트 양자화 행렬-벡터곱(32개씩 블록 척도),
인과 어텐션(머리 하나). 파일은 `커널/` — `*.cu` 는 단순한 CUDA 구현(nvcc 로 확인하지 않음: 툴킷이 없다),
`*.가상.gl` 은 글 서술형. 표기량은 `python research/gpu/종이시험/재기.py`.

## 결과 요약

| 잰 것 | CUDA | 글 서술형 (가상) |
|---|---|---|
| 컴파일러가 아는 의미 (42개 중) | **11** — 원소 정밀도 7, `const` 4 (읽기 전용만 알고 쓰는 대상은 모름) | **40** — 못 아는 둘은 공식(1/√d)과 인과 방향 |
| 실수 28개 중 컴파일 전에 막는 것 | **0** (호출부가 `const` 포인터를 들고 있을 때만 바꿔 넘김 3개를 거부) | **21** = 컴파일 거부 14 + 실수를 적을 자리가 없음 7 |
| 둘 다 못 막는 것 | 7 | 7 — 전부 **식·경계의 방향·의도** |
| 표기량 (토큰 / 글자 / 줄) | 939 / 1803 / 67 | 343 / 560 / 21 (0.37 / 0.31 / 0.31) |

막는 21개는 두 갈래다.

- **실수를 적을 자리가 없음 (7)** — 인덱스 계산·반복 경계·크기 인자가 코드에 없어서 생기지 않는 실수
  (보폭, off-by-one, 크기 인자 순서, 니블 순서, 영점). 이것은 einsum·NumPy 같은 **배열 언어의 공통 성질**이고
  글만의 몫이 아니다. 표기량이 짧은 이유도 대부분 여기 있다.
- **컴파일 거부 (14)** — 의미가 타입과 문법에 있어서 어긋나면 거부되는 실수: 축 이름 불일치(정규화·축소 축
  틀림, 전치 혼동), 종류(로짓·확률) 불일치, 정밀도 규칙(누적은 짧은실수 이상), 블록 척도의 블록 크기,
  역할 조사(같은 타입 인자의 바꿔 넘김, D-30). **einsum 과 견준 글의 몫은 이쪽**이다 — einsum 의 축은 문자열
  속 글자라 종류·정밀도·역할을 모르고, 이름 붙은 텐서·타입 주석은 다른 언어에서 선택 사항이다.

못 막는 7개는 한 부류다: 크기 조정 공식(√ 를 빠뜨림), ε 의 위치, 평균 대신 합, 인과 가리개의 off-by-one·방향,
덮어쓰기 대 더하기. **값이 어디로 가고(자리) 무슨 값인지(정체)** 는 문법이 담지만, **무엇을 계산하려는가(의도)**
는 담지 못한다. 의미 손실의 갈래로 보면 문법이 지키는 범위와 못 지키는 범위가 깨끗하게 갈린다.

## 가상 문법 v0

종이 시험을 위해 정한 규칙이다. 명세가 아니다 — 모호한 곳은 2단계에서 명세로 정한다.

1. **텐서 매개변수**: `타입 [종류] 이름[축, …]조사`. 축은 명사(`토큰`, `특징`, `열쇠`). 크기는 실행할 때 **축 이름으로**
   묶인다 — 크기를 위치 인자로 넘기지 않는다. 축 순서는 타입의 일부다(저장 순서).
2. **원소 타입**: `반실수`(16비트, bf16), `짧은실수`(fp32), `4비트정수(영점 8)` — 두 개씩 한 바이트, 아래 4비트 먼저.
   저장 형식은 타입이 정한다.
3. **종류(의미 꼬리표)**: `로짓`, `양수`, `확률(축에 걸쳐)`, `척도`. 종류가 다른 값을 섞으면 오류.
   `지수함수` 의 값은 `양수`, `양수 / 그 값을 축에 걸쳐 더한 값` 은 `확률(그 축에 걸쳐)` 로 추론된다.
   `으로 종류` 로 밝힐 수 있지만, 추론된 종류와 다르면 오류다.
4. **역할 조사**: `에` 는 쓰는 대상, `에서`·`와/과`·`로`·`을/를` 는 읽기만. 읽기만 하는 자리에 쓰면 오류.
   같은 타입인 매개변수는 조사가 달라야 바꿔 넘김이 거부된다(D-30).
5. **원소별 식**: 텐서끼리의 산술은 **축 이름으로 맞춘다**. 같은 이름은 같은 축, 한쪽에만 있는 축은 퍼진다.
6. **줄이기**: `축에 걸쳐 더한 값`, `축에 걸쳐 평균낸 값`, `축 중 가장 큰 값`. 줄일 축을 이름으로 적는다.
7. **대입** `대상 = 식`: 식의 축 집합이 대상과 같아야 한다. 줄이기·퍼뜨리기는 식에서 밝힌다.
8. **축별 동사**: `X를 축별로 V한 값` — 그 축의 칸마다 따로, 나머지 축에 걸쳐 V. `소프트맥스` 의 결과 종류는
   `확률(나머지 축에 걸쳐)`.
9. **정밀도**: 넓히기는 암시, 좁히기는 `으로 반실수` 로 밝힌다. **줄이기(합)의 누적은 짧은실수 이상** —
   그보다 낮게 누적하려면 밝힌다.
10. **블록 척도**: `척도 S[출력, 입력 32개씩]` — 입력 축을 32칸씩 묶은 축. `W를 S로 푼 값` 은 W 의 각 칸에 그 칸이
    속한 묶음의 척도를 곱한다(블록 크기와 영점은 타입에서).
11. **위치와 가리개**: `위치(축)` 은 그 축에서의 번호, `특징의 크기` 는 축의 크기.
    `X에서 조건인 칸을 가리다` 는 그 칸을 음의 무한대로(로짓에만).

## 커널별

표의 표시: **거부** — 컴파일 오류, **자리 없음** — 그 실수를 적을 코드가 없음, **통과** — 컴파일됨(못 막음),
**△** — 호출부가 `const` 포인터를 들고 있을 때만 거부.

### 1. 소프트맥스

```
[짧은실수 로짓 z[토큰, 어휘]에서 짧은실수 확률(어휘에 걸쳐) p[토큰, 어휘]에 소프트맥스]는 {
    짧은실수 로짓 큰값[토큰] = z의 어휘 중 가장 큰 값.
    짧은실수 양수 지수[토큰, 어휘] = 지수함수(z - 큰값).
    p = 지수 / 지수를 어휘에 걸쳐 더한 값.
}
```

| 의미 | 갈래 | CUDA 컴파일러 | 글 |
|---|---|---|---|
| z 는 로짓 | 정체 | 이름·주석뿐 | 타입 |
| p 는 어휘에 걸친 확률 | 정체 | 이름·주석뿐 | 타입 (식에서 추론해 대조) |
| z·p 의 축 [토큰, 어휘] | 자리 | 인덱스 계산 속 | 타입 |
| 정규화 축은 어휘 | 자리 | 반복문 구조 속 | 줄이기의 축 이름 |
| 원소 정밀도 fp32 | 정체 | 안다 (`float`) | 안다 |
| z 는 읽기만 | 흐름 | 안다 (`const`) | 안다 (`에서`) |
| p 에 쓴다 | 흐름 | 이름뿐 | 안다 (`에`) |
| T·V 가 어느 축의 크기인가 | 자리 | 인자 순서뿐 | 축 이름으로 묶임 |

| 실수 | CUDA | 글 | 근거 |
|---|---|---|---|
| 정규화 축을 토큰으로 | 통과 | 거부 | 큰값[토큰]·확률(어휘에 걸쳐)과 축이 어긋남 |
| 행 보폭 `t * T` (V 대신) | 통과 | 자리 없음 | 인덱스 계산이 없다 |
| 이미 확률인 값을 다시 소프트맥스 | 통과 | 거부 | 입력 종류는 로짓 |
| z·p 를 바꿔 넘김 | △ | 거부 | 역할 `에서`·`에`, 종류 |
| T·V 를 바꿔 넘김 | 통과 | 자리 없음 | 크기는 축 이름으로 |
| 최댓값 빼기를 빠뜨림 (넘침) | 통과 | 통과 | 알고리즘 |

### 2. 행렬곱 (bf16 입력, fp32 누적)

```
[반실수 A[행, 공유]에서 반실수 B[공유, 열]과 짧은실수 C[행, 열]에 행렬곱]는 {
    C = (A × B)를 공유에 걸쳐 더한 값.
}
```

| 의미 | 갈래 | CUDA 컴파일러 | 글 |
|---|---|---|---|
| A·B 원소 bf16, C 원소 fp32 | 정체 | 안다 | 안다 |
| 누적은 fp32 이상이어야 함 | 정체 | 모름 (`acc` 선언은 따로) | 규칙 9 |
| A 축 [행, 공유] | 자리 | 인덱스 속 | 타입 |
| B 축 [공유, 열] — 전치 여부 | 자리 | 인덱스 속 | 타입 |
| C 축 [행, 열] | 자리 | 인덱스 속 | 타입 |
| 줄이는 축은 공유 | 자리 | 반복문 | 식 |
| A·B 읽기, C 쓰기 | 흐름 | `const` 만 | 조사 |
| M·N·K 대응 | 자리 | 인자 순서 | 축 이름 |

| 실수 | CUDA | 글 | 근거 |
|---|---|---|---|
| [N][K] 로 저장된 B 를 [K][N] 으로 읽음 (전치 혼동) | 통과 | 거부 | 축 순서는 타입 — 호출부 텐서와 어긋남 |
| bf16 으로 누적 | 통과 | 거부 | 누적은 짧은실수 이상, 낮추려면 밝힘 |
| M·N 을 바꿔 넘김 | 통과 | 자리 없음 | 크기는 축 이름으로 |
| `k <= K` (경계 밖 읽기) | 통과 | 자리 없음 | 반복 경계가 없다 |
| 더해야 하는데 덮어씀 | 통과 | 통과 | 의도 |

### 3. RMS 정규화

```
[짧은실수 x[토큰, 특징]에서 짧은실수 w[특징]과 짧은실수 y[토큰, 특징]에 짧은실수 eps로 RMS정규화]는 {
    짧은실수 크기[토큰] = 제곱근((x × x)를 특징에 걸쳐 평균낸 값 + eps).
    y = x / 크기 × w.
}
```

| 의미 | 갈래 | CUDA 컴파일러 | 글 |
|---|---|---|---|
| x·y 의 축 [토큰, 특징] | 자리 | 인덱스 속 | 타입 |
| w 는 특징마다 하나 | 자리 | `w[d]` 인덱스 속 | 타입 w[특징] |
| 정규화 축은 특징 | 자리 | 반복문 | 식 |
| 원소 정밀도 fp32 | 정체 | 안다 | 안다 |
| x·w 읽기, y 쓰기 | 흐름 | `const` 만 | 조사 |
| eps 는 스칼라 수단 | 흐름 | 안다 (`float`) | 안다 (`로`) |
| T·D 대응 | 자리 | 인자 순서 | 축 이름 |

| 실수 | CUDA | 글 | 근거 |
|---|---|---|---|
| 토큰 축에 걸쳐 평균 | 통과 | 거부 | 크기[토큰] 과 축이 어긋남 |
| w 를 토큰 번호로 읽음 (`w[t]`) | 통과 | 거부 | w 의 축은 특징 — 토큰과 맞출 수 없음 |
| ε 를 제곱근 밖에 더함 | 통과 | 통과 | 식 |
| 평균 대신 합 | 통과 | 통과 | 식 |
| x·y 를 바꿔 넘김 | △ | 거부 | 역할 |

### 4. 4비트 양자화 행렬-벡터곱 (32개씩 블록 척도)

```
[4비트정수(영점 8) W[출력, 입력]에서 짧은실수 척도 S[출력, 입력 32개씩]으로 짧은실수 x[입력]과 짧은실수 y[출력]에 양자화곱]는 {
    y = ((W를 S로 푼 값) × x)를 입력에 걸쳐 더한 값.
}
```

| 의미 | 갈래 | CUDA 컴파일러 | 글 |
|---|---|---|---|
| W 는 4비트, 두 개씩 한 바이트, 아래 4비트 먼저 | 정체 | `uint8_t` 뿐 — 형식은 코드 속 | 타입 |
| W 의 영점 8 | 정체 | 코드 속 상수 | 타입 |
| S 는 척도, 출력마다·입력 32개마다 하나 | 정체·자리 | 이름·인덱스 속 | 타입 |
| S 원소 fp32 | 정체 | 안다 | 안다 |
| x[입력], y[출력] | 자리 | 인덱스 속 | 타입 |
| 줄이는 축은 입력 | 자리 | 반복문 | 식 |
| 누적은 fp32 이상 | 정체 | 모름 | 규칙 9 |
| W·S·x 읽기, y 쓰기 | 흐름 | `const` 만 | 조사 |
| N·K 대응 | 자리 | 인자 순서 | 축 이름 |

| 실수 | CUDA | 글 | 근거 |
|---|---|---|---|
| 척도를 64개씩으로 읽음 (블록 크기 불일치) | 통과 | 거부 | 블록 크기는 타입 — 32개씩 만든 척도와 어긋남 |
| 니블 순서 반대 | 통과 | 자리 없음 | 저장 형식은 타입이 정한다 |
| 영점을 빠뜨림 | 통과 | 자리 없음 | 영점은 타입 |
| 척도 행 보폭 실수 | 통과 | 자리 없음 | 인덱스가 없다 |
| fp16 척도를 fp32 로 읽음 | 통과 | 거부 | 호출부 타입이 어긋남 |
| x·y 를 바꿔 넘김 | △ | 거부 | 역할, 축 이름 |

### 5. 인과 어텐션 (머리 하나)

```
[짧은실수 Q[질의, 특징]를 짧은실수 K[열쇠, 특징]과 짧은실수 V[열쇠, 특징]에서 짧은실수 O[질의, 특징]에 인과주의]는 {
    짧은실수 로짓 점수[질의, 열쇠] = ((Q × K)를 특징에 걸쳐 더한 값 / 제곱근(특징의 크기)) 으로 로짓.
    점수에서 위치(열쇠)가 위치(질의)보다 큰 칸을 가리다.
    짧은실수 확률(열쇠에 걸쳐) 무게[질의, 열쇠] = 점수를 질의별로 소프트맥스한 값.
    O = (무게 × V)를 열쇠에 걸쳐 더한 값.
}
```

말로 하면 "Q를 K와 견주어 V에서 모아 O에 담는다" — 그래서 같은 타입의 네 텐서가 **조사가 모두 다르다**.
CUDA 에서는 넷 다 `float*` 라 어느 둘을 바꿔 넘겨도 컴파일된다.

| 의미 | 갈래 | CUDA 컴파일러 | 글 |
|---|---|---|---|
| Q·K·V·O 의 축 | 자리 | 인덱스 속 | 타입 |
| 점수는 특징 축으로 내적 | 자리 | 반복문 | 식 |
| 점수는 로짓 | 정체 | 모름 | 타입 (`으로 로짓` 은 쓴 사람의 단언) |
| 무게는 열쇠에 걸친 확률 | 정체 | 모름 | 타입 (소프트맥스 결과와 대조) |
| 출력은 열쇠 축으로 가중합 | 자리 | 반복문 | 식 |
| K 와 V 는 역할이 다름 | 흐름 | 모름 (같은 타입) | 조사 `과`·`에서` |
| Q·K·V 읽기, O 쓰기 | 흐름 | `const` 만 | 조사 |

## 한계와 편향

- **설계자가 문법과 실수를 함께 골랐다.** 막을 수 있는 실수를 고르기 쉽다. 0단계에서 공개된 실제 버그
  (Anthropic 사후 분석, llama.cpp·vLLM·FlashAttention·PyTorch 이슈)를 모아 같은 표로 다시 잰다 — 그 결과가
  이 문서를 이긴다.
- **가상 문법은 컴파일되지 않는다.** 모호성(`별로` 와 `마다` 의 경계, 종류 추론 규칙, 줄이기 동사 목록)과
  구현 비용은 2단계에서 드러난다. 특히 규칙 3 의 종류 추론은 주장이 크다 — 증명할 일이다.
- **짧음은 결과가 아니다.** 표기량의 대부분은 배열 언어의 추상에서 온다. 비교의 핵심은 막는 실수의 수와 종류다.
- **CUDA 판은 단순 구현**이다(스레드 하나가 한 줄). 빠른 구현일수록 인덱스·공유 메모리·동기화가 늘어 CUDA 쪽
  실수 자리는 더 많아진다 — 이 표는 CUDA 에 유리한 쪽으로 기운 셈이다.
- 성능은 재지 않았다.
