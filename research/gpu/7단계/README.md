## 속도 — 7번의 중앙값

생성 토큰당 ms (짧은 문맥 = 문장 1 의 5토큰 · 문맥 960). 양자 판과 llama.cpp 는 같은 실행에서 번갈아, 짧은실수 판 · PyTorch eager · HF 는
GPU 메모리(12 GB)에 둘이 함께 올라가지 않아(가중치 6.4 GB 씩) 같은 실행에서 차례로 하나씩.

| | 짧은실수 | F16 | Q8_0 | Q4_0 |
|---|---|---|---|---|
| **글** | **14.06 · 15.38** | **7.14 · 7.83** | **4.54 · 5.24** | **3.16 · 3.87** |
| PyTorch eager | 15.68 · 21.26 | | | |
| HF transformers | 19.52 · 25.02 | | | |
| llama.cpp | | 8.53 · 9.03 | 5.18 · 5.65 | 3.61 · 4.11 |
| 글 / 비교 대상 | 0.90 · 0.72 (eager) | 0.84 · 0.87 | 0.88 · 0.93 | 0.88 · 0.94 |

Q4_0 짧은 문맥은 초당 316 토큰(llama.cpp 277). small 에서보다 차이가 줄었다 — XL 의 생성은 가중치 읽기(Q4_0 927 MB / 475 GB/s = 1.95 ms)가
토큰 시간의 62% 라 둘 다 그 바닥에 가깝다.

프롬프트 처리 + 첫 토큰 (ms, 128 · 512 · 1024):

| | 짧은실수 | F16 (기록) | Q8_0 | Q4_0 |
|---|---|---|---|---|
| 글 | 24.8 · 82.4 · 158.6 | 29.9 · 92.3 · 176.4 | 14.5 · 47.5 · 97.2 | 14.3 · 46.2 · 92.0 |
| PyTorch eager | **26.9 · 76.2 · 153.2** | | | |
| HF transformers (기록, 1023) | 30.3 · 83.3 · 182.7 | | | |
| llama.cpp | | **13.6 · 26.4 · 53.7** | **11.9 · 29.8 · 58.8** | **10.8 · 28.1 · 55.4** |
| 글 / 비교 대상 | 0.92 · 1.08 · 1.04 | 2.2 · 3.5 · 3.3 | 1.23 · 1.60 · 1.65 | 1.33 · 1.65 · 1.66 |

**왜 미달인가.** 큰 모델의 프롬프트는 계산이 지배한다 — 1024 토큰의 선형 층 계산은 3.0 × 10¹² 연산(곱과 합을 둘로 센 것 — 곱합 1.5 × 10¹²). 정수 블록 계약은 활성값을 자리 넷으로
두므로 텐서 일이 llama.cpp(활성값 한 자리, 8 비트)의 **네 배**다. 글의 Q4_0 프롬프트 92 ms 로 연산 수를 나누면 1.3 × 10¹⁴ /s(int8 최고치
3.2 × 10¹⁴ 의 41%, llama.cpp 의 유효 5.5 × 10¹³ 의 2.4배 — 프롬프트 전체 시간으로 나눈 값이라 타일 자체는 더 빠르다)인데, 일이 네 배라
1.65배 느리다. small 에서 이긴 것은 행렬이 작아 커널 사이의 빈틈 · 네 자리 바꾸기 · 어텐션의 몫이 컸고 그것을 묶기로 줄였기 때문이다.
짧은실수 판은 PyTorch eager(cuBLAS SGEMM — TF32 끔이 기본)와 같은 짧은실수 곱해더하기인데, 가닥 넷 약속의 합치기 · 끝손질 몫(3단계
3f 와 같은 까닭)으로 512 · 1024 에서 8% · 4% 길다(128 에서는 띄우기 비용이 작아 짧다). F16 판은 가닥 약속의 CUDA 코어 곱해더하기라
텐서 코어의 llama.cpp 보다 2.2~3.5배 길다.

|---|---|---|---|

| HF transformers fp32 | 1.62 × 10⁻⁷ | 1.61 × 10⁻⁷ | 1.65 × 10⁻⁷ |
| 배수 (기준 2 안) | 1.60 | 1.56 | 1.73 |

## 어떻게

- **생성기**(3단계/커널생성.py): 너비 · 머리 수 · 층 수 · 확장 폭 · 낱말 수가 매개변수(`크기들["XL"]`). small 의 소스 일곱은 바꾸기 전과
  바이트까지 같다(git 대조). 다른 것은 크기에서 나오는 줄뿐: 층정규화의 가상 스레드가 맡는 칸 수(1600 = 256 × 6 + 64 라 k 마다 6 · 7
  칸), 층정규화정수는 블록이 행 넷(판 = 4 × 1600 칸), 정수 줄 판 · 메가커널은 깊이 6400 의 x 와 네 자리를 판에 따로 둘 수 없어
  레지스터로 읽어 제자리에 바꾼다(정수판바꾸기제자리 — 같은 바꾸기), 양자 메가커널의 칸 묶음 5(블록 수 50 · 200), 메가커널 판의 자리들,
  어텐션의 머리 25(블록 120 = 25 × 4 + 20 — 남는 블록 20 은 어텐션에서 쉰다).
- **호스트**(3단계/글gpt2.py): 가중치에서 크기를 읽어(self.D · NH · NL · V) 모듈을 고른다. 3단계/토치gpt2.py 도 크기를 읽는다.
- **fp64 참값**: 모델 전체의 fp64 는 12.8 GB 라 GPU 에 다 들어가지 않는다 — 짧은실수 가중치를 GPU 에 두고 층마다 fp64 로 올려 계산.
- **값과 상관없이 고른 것**: XL 메가커널은 가중치 L2 미리 올리기를 끈다 — 행렬 하나(짧은실수 c_fc 41 MB)가 L2(48 MB)를 거의 채워 올린
  것이 쓰기 전에 밀려나고 DRAM 대역만 썼다(재서 정함: 짧은실수 17.0 → 14.1 ms/토큰, 16 MB 까지만 올려도 15.0, Q4_0 은 같다).

## 경과 (판정 기준은 그대로)

- 먼저 XL 모듈 다섯을 만들어 네 형식의 한번에 · 하나씩 · 메가커널 비트가 같음을 보고, 개발용 재기로 생성 · 프롬프트를 쟀다 — 프롬프트는
  처음부터 llama.cpp 의 1.7배였다. 단계 시간 나누기로 메가커널의 미리 올리기 몫을 찾아 끄고 판정을 쟀다.
- HF 의 프롬프트 1024 는 위치표(1024 줄) 때문에 생성(1토큰)이 1023 까지라 1023 으로 쟀다(기록).
- 판정 수치는 재기8.py 한 실행의 값이다.
