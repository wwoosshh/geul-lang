## 2a 주소 공간 — 통과

규칙: **커널의 참조 매개변수는 전역 메모리를 가리키고, 거기서 나온 주소(색인·필드·복사)도 전역이다.** 타입처럼 전해질 뿐
추측하지 않는다 — 한 변수에 서로 다른 공간이 섞이면 그 커널은 예전처럼 범용 주소로 돌아간다. 그리고 주소가 load/store 의
자리로만 쓰이는 지역 변수는 레지스터에 둔다.

| 커널 | 전 (레지스터 / 스택) | 뒤 | 결과 |
|---|---|---|---|
| 벡터덧셈 | 16 / **40 B** | 14 / **0** | 1,048,576개 중 틀린 값 0 (손 PTX 12 / 0) |
| 벡터덧셈_보폭 | — / 스택 있음 | 16 / 0 | 틀린 값 0 |
| 곱더하기 | 16 / 48 B | 16 / 0 | CPU 의 글과 비트가 다른 값 0 |
| 제곱차 | — | 14 / 0 | x·x − x·x 가 0 이 아닌 칸 0 |
| 행렬곱 (감사 A1) | 30 / 88 B | 40 / 0 | B 14가지 불변, CPU 와 비트 같음. **19.8 ms → 3.7 ms** (B = 4096) |

## 2b 타일 — 통과

`타일행렬곱.gl` 은 32 × 32 블록이 입력·가중치의 조각을 공유 메모리에 올리고(동기화) 각 스레드가 자기 칸에 k 를 차례로 더한다.
연구용 내장 일곱(블록안가로·블록안세로·블록가로·블록세로·공유메모리0·1·동기화)을 쓴다 — 언어가 아니라, 타일을 손으로 써 보기 위한
것이다. 나중에는 배분어(`씩`·`마다`)에서 컴파일러가 이 꼴을 만들어야 한다(주장 C2).

| 잰 것 | 결과 |
|---|---|
| 타일 판의 출력 전체가 기준 판과 다른 B (14가지 중) | **없음** — 비트까지 같다 |
| 0번 행이 B = 1 과 다른 B | 없음 (행 불변) |
| 0번 행과 CPU 기준(같은 순서, 연산마다 반올림)이 다른 칸 | 0 |
| 시간 (B = 4096, 10회 중앙값) | 기준 판 3.67 ms → **타일 판 2.38 ms**, PyTorch `F.linear` 0.25 ms |

처음(19.8 ms)보다 8.3배 빨라졌고 PyTorch 와의 차이는 94배에서 약 9.6배로 줄었다. 남은 차이의 일부는 의미의 값이다 — PyTorch(cuBLAS)는
곱과 덧셈을 FMA 하나로 하고(반올림 한 번) 더하는 순서도 B 에 따라 바꾸지만, 글은 소스대로 연산마다 반올림하므로 같은 일에 명령이
둘 든다. 같은 의미로 견주면(주장 C 의 원칙) 차이는 더 작다 — 그 비교는 레지스터 타일까지 들어온 뒤에 다시 잰다.

## 2c 범위 검사 — 통과

실수 → 정수(·중간정수) 변환은 값이 대상의 범위 [lo, hi) 밖이거나 NaN 이면, 실수 → 짧은실수 변환은 유한한 값이 무한이 되면, 커널이
모듈의 오류 칸 `__geul_err` 에 비트를 켠다(1 정수, 2 짧은실수). 호스트가 실행 뒤에 읽는다.

| 입력 | 오류 칸 | 검사가 없을 때 GPU 가 조용히 낸 값 (정수 / 중간정수 / 짧은실수) |
|---|---|---|
| 범위 안 100만 개 (\|x\| < 2e9) | 0 — 결과가 정답과, 검사 없는 판과 비트까지 같음 | — |
| 3e9 | 1 | 3000000000 / **2147483647** / 3e9 |
| 2^31 | 1 | 2147483648 / **2147483647** / 2147483648 |
| 2^31 − 1 · −0.5 | 0 · 0 | (범위 안) |
| 1e19 | 1 | **9223372036854775807** / 2147483647 / 1e19 |
| NaN | 1 | **−9223372036854775808** / −2147483648 / NaN |
| 1e39 | 3 | 9223372036854775807 / 2147483647 / **inf** |
| inf | 1 | (정수 변환이 범위 밖, 짧은실수는 이미 무한이라 오류가 아님) |

비용: 1,600만 개에서 검사 판 1.009 ms, 검사 없는 판 1.034 ms — 잴 수 있는 차이가 없다(메모리가 병목인 커널).
같은 변환을 x86 CPU 는 범위 밖에서 정수의 최솟값을 내고 GPU 는 끝값으로 포화한다 — 이 규칙이면 둘 다 "오류"가 되어 CPU 와 GPU 의
의미가 갈리지 않는다. CPU 백엔드에 같은 규칙을 넣는 것과 글로 쓴 호스트(`쿠다.gl`)가 오류 칸을 읽게 하는 것은 다음 일이다.
f16·bf16 같은 낮은 정밀도 타입은 아직 언어에 없어서, 감사에서 본 "중간값이 f16 범위를 넘는" 꼴은 그 타입이 들어올 때 이 검사를
산술로 넓혀야 한다.
