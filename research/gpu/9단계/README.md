# 9단계 — 정수 KV 계약: 어텐션도 정수 텐서 코어로, 긴 문맥까지 (docs/17 §7 "9단계")

사용자의 물음(2026-10-09): 실사용은 모델이 더 크고 대화가 쌓여 로컬에서도 문맥이 10만까지 가는데, 프롬프트 누적에서 계속 뒤지면 실사용에서
성능이 떨어지는 것 아닌가. 맞다 — 그리고 문맥이 길수록 더 뒤진다. 8단계까지의 어텐션은 짧은실수 CUDA 코어로 돌고 그 일은 문맥의 제곱으로
는다(합성 긴 모델: 4096 에서 llama.cpp 의 0.64배로 이기고, 16384 에서 1.50배로 진다). llama.cpp 는 어텐션을 f16 텐서 코어(flash
attention)로 돌린다 — f16 누적의 반올림이 정해져 있지 않아 계약 밖의 길이다. 남은 길은 KV 캐시를 정수 블록 계약으로 두고 Q·Kᵀ 와 P·V 를
정수 텐서 코어의 정확한 합으로 하는 것 — 활성값(8단계)과 같은 문장으로. 판정은 실험보다 먼저 적었다(a0bf50a).

## 계약 — 정수 KV (자리 둘)

c_attn 의 출력 q · k · v 를 8단계의 활성값과 같은 문장으로 바꾼다(d 32 칸 블록마다 E = ⌊log₂ max|x|⌋ [−98, 100], n = 가까운정수(x · 2^(13−E)),
|n| ≤ 2¹⁴, 균형 256진 두 자리). 키 · 값은 그 자리와 지수(E + 114, 바이트 하나)로 캐시에 남는다 — 칸마다 2 바이트, 블록마다 1 바이트(반실수
KV 의 1.03배). 질의 하나(위치 p, 머리 h)의 어텐션 — 키 조각 σ(64 개씩)와 접기는 4단계의 순서 약속 그대로이고, 조각 안이 바뀐다:
1. 점수 s_t = 0.125 × Σ_b (u_b,t × 2^(E_q,b − 13)) × 2^(E_k,t,b − 13). 블록 b 마다 u_b,t = 짧은실수(Σ_{d∈b} n_q,d · n_k,t,d) — 자리 짝 넷의
   정수 곱의 합 2¹⁶S₁₁ + 2⁸(S₁₀ + S₀₁) + S₀₀ 을 정확히(35 비트) 구해 짧은실수로 반올림 하나. 거듭제곱 곱은 정확, 블록 둘의 합은 곱해더하기
   하나. 가린 키(t > p)는 −3 × 10³⁸.
2. m_σ = max s_t, e_t = 적힌지수(s_t − m_σ) — 적힌지수는 다항식(Cephes expf 의 계수, 곱해더하기 사슬, 2ⁿ 은 지수 비트 더하기; n 은 정확한
   곱 x·log₂e 를 마법수 1.5·2²³ 를 더하는 곱해더하기로 반올림). 모든 연산이 IEEE 짧은실수라 CPU 가 비트까지 같은 값을 낸다. 접기의 비율도.
3. l_σ = 짧은실수(Σ 가까운정수(e_t · 2²³)) × 2⁻²³ — 정수로 정확히 더한 뒤 반올림 하나(순서 무관).
4. o_σ,d: 값의 블록 b 마다 e′_t = e_t × 2^(E_v,t,b − 13) (정확), 키 32 개 블록 j 마다 e′ 를 자리 둘로(n_e = 가까운정수(e′ · 2^(13 − E_e)) —
   정확한 곱을 마법수 2²³ + 128 로 반올림), u_j,d = 짧은실수(Σ n_e,t · n_v,t,d) (정확한 합, 반올림 하나), o_σ,d = u_0,d × 2^(E_e,0,b − 13) +
   u_1,d × 2^(E_e,1,b − 13) (곱해더하기 하나).
5. 접기 (M, L, O) 와 출력 O / L 은 그대로 — 출력은 c_proj 의 자리 둘로 바로.

정수 합은 순서와 상관없으니 프롬프트(텐서 코어 mma)와 생성(dp4a)이 같은 비트를 내는 것이 계약에서 바로 나온다. CPU 참조는
[6단계/정수계약.py](../6단계/정수계약.py) 의 `어텐션` · `적힌지수` · `키캐시` · `값캐시` · `e자리`.

**판정 전에 잰 것** 은 docs/17 9단계 절에: llama.cpp 자신의 Q8_0 KV 는 F16 KV 보다 느리고(1.13~1.19배) 더 잃는다; 흉내 정확도 — 정수 KV
자리 둘 2.3 × 10⁻⁴ / 1.3 × 10⁻⁴(반실수 KV 의 0.85 · 0.63배; llama.cpp 식 Q8_0 KV 는 40배); 긴 문맥의 llama.cpp 와 지금의 글; 물리적 바닥.

## 어떻게

- **캐시 배치.** 키 [문장·머리][자리 2][위치][64 바이트] — 활성값 배치 그대로(낱말 차례 0 4 1 5 2 6 3 7)라 mma 의 B 조각을 64 비트 읽기
  하나로, dp4a 의 낱말을 그대로 쓴다. 값 [문장·머리][키 블록 32][자리 2][d 64][낱말 8] — 낱말 2c + h 가 키 16h + 2c, +1, +8, +9 의 d 번째
  자리: mma 의 B 조각(열 d, k 네 칸)이 바로 읽는 차례이고 점수 C 조각(키 2t, 2t+1 이 레인에)에서 e′ 의 A 조각이 셔플 없이 나온다. 지수는
  E + 114 바이트(2^(E−13) 의 비트 = 바이트 << 23).
- **프롬프트(정수어텐션).** 블록 하나(워프 넷, 128 스레드)가 (머리, 질의 64) — 워프마다 질의 16. 조각마다 키 · 값 자리(16 KB)를
  비동기복사로 판에(두 조각 겹쳐, 키의 16 바이트 조각은 (q ^ (키 & 2)) 자리 — 뱅크 겹침 없음), 지수는 스레드가 제 몫을 전역에서 읽어
  2^(E−13) 으로 미리 둔다. 점수 32 mma + 가중합 32 mma 를 레인마다 정수곱읽기(짧은실수만으로 — FastTwoSum, 범위 검사가 붙는 변환 없이)로
  읽는다. 2⁻²³ 눈금의 합 · e′ 의 자리는 마법수 덧셈으로(가까운정수의 범위 검사를 더운 길에서 뺀다 — 값은 같다), 네 바이트는
  바이트고르기(prmt)로 낱말에. 출력 O / L 은 c_proj 의 자리 둘로.
- **생성(정수조각계산워프).** 워프 하나가 조각 하나 — 레인 r 이 키 2r, 2r+1 의 점수(dp4a 64 × 2)를, e′ 자리를 판에 값 캐시와 같은 낱말
  차례로 모아, 레인 r 이 d = 2r, 2r+1 의 가중합(dp4a). 메가커널은 어텐션 단계의 블록이 제 머리의 q 를 바꾸고 마지막 조각을 맡을 블록이 새
  위치의 키 · 값을 캐시에 쓴다(c_attn 단계는 q · k · v 를 짧은실수로 둔다 — 장벽을 더하지 않는다; 값은 프롬프트의 끝손질과 같다).
  줄 판(행 넷까지)은 KV정수로 를 거쳐 행마다 정수조각어텐션 — 같은 비트.
- **타일의 _KV정수 끝손질.** 32 열 블록마다 지수 · 자리 둘을 구해 q 는 자릿값q 에, 키는 캐시에(활성값 배치 그대로 16 바이트씩), 값은 행
  조각 16 이 위치 16 과 나란할 때(위치시작 · 묶음안행수가 16 의 배수) 이웃 레인의 두 바이트를 받아 키 넷의 낱말로, 아니면 바이트 하나씩
  (세 문장 묶음 — 값은 같다). 열수 밖의 블록(XL: 4800 열이 256 의 배수가 아니다)은 건너뛴다 — 처음에 이것을 빠뜨려 XL 의 값 지수에
  쓰레기가 쓰였고(오류 칸이 켜졌다) 캐시 바이트 대조가 잡았다.
- **접기.** 정수접기는 빠른접기와 같은 순서 약속에 적힌지수, 조각 256 개씩 묶어 몇 묶음이든(최대길이 131072 — 조각 2048).
- 값이 같음은 세 겹으로: CPU 참조(실제 층의 q · k · v, 합성 16384), 모든 길(프롬프트 타일 · 줄 판 · 메가커널 · 세 문장 묶음)의 로짓과 캐시
  바이트, 4c.

## 경과 (판정 기준은 그대로 — 해 본 것과 안 된 것)

첫 정수어텐션(2026-10-09, small 1024 한 층): 181 µs — 8단계의 짧은실수 어텐션(129)보다 느렸다. 번갈아 잰 변형으로 시간을 나눠 보니 PV 95 ·
점수 23 · 적힌지수 0 · "1 반올림 읽기 대 2 반올림" 58 — 범위 검사가 붙는 실수 → 정수 변환(가까운정수 · 으로 중간정수: setp 둘 + 조건
쓰기)이 더운 길에 192 개씩 있었다. 변환을 모두 마법수 덧셈 · FastTwoSum 으로 바꾸고(값은 같다 — CPU 참조와 비트 대조), 바이트고르기(prmt)를
더하자 79 µs. 지수를 2^(E−13) 로 미리 풀고 0.125 를 q 의 거듭제곱에 접고 가림을 걸친 조각에서만 하자 72 µs(small 1024 — 바닥 20 의 3.6배),
XL 1024 147 µs(바닥 42 의 3.5배), small 4096 766 µs(바닥 322 의 2.4배).
