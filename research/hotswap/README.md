# 핫스왑 탐침 (2026-09-20)

[docs/14-핫스왑-방향.md](../../docs/14-핫스왑-방향.md)의 "확인한 사실"을 뒷받침하는 최소 탐침 두 개.
방향 결정용 증거이며 제품 코드가 아니다.

## 탐침-대입.gl — 글이 임의 주소를 함수로 부를 수 있는가

```
python ref/geulc.py research/hotswap/탐침-대입.gl -o build/탐침.exe
```

결과: **거부됨.**

```
오류: 초기화: '공허 참조' 타입을 '[ -> 정수]'에 넣을 수 없습니다 — 호환되지 않는 타입
```

⇒ VirtualAlloc 이 준 주소를 함수 포인터에 담아 부를 수 없다. 핫스왑은 userland 글
라이브러리로 시제품을 만들 수 없고, 첫 이정표부터 컴파일러·백엔드 작업이 필요하다.

## viability.c — 이 머신에서 협조적 핫스왑이 물리적으로 되는가

글이 아니라 C 다. 이 Windows 머신과 보안 SW 아래에서 OS 원시 기법이 협조적 핫스왑을
허용하는지만 본다. kernel32 만 쓴다(글의 불변식과 같다). `zig cc` 로 컴파일했다.

```
zig cc research/hotswap/viability.c -o build/viability.exe && build/viability.exe
```

결과: **통과.**

```
v1 = 111
v2 = 222
PASS 협조적 핫스왑 기계-수준 가능 (본문 교체 반영됨)
```

VirtualAlloc RW → 본문 기록 → RX 로 좁힘(W^X) → 포인터 호출 → RW 로 되돌려 교체 → RX →
재호출. 주입 없음, 프롤로그 덮어쓰기 없음. 세션을 죽이던 보안 SW 가 이 협조적 방식은
막지 않았다.
