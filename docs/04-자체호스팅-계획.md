# 3단계 — 자체호스팅 계획

**상태**: 진행 중 (2026-09-03). 1단계 렉서·2단계 파서·3단계 의미 분석+IR 하강 완료 — `self/`의 렉서·파서·타입·의미·하강이 참조 구현과 118개 입력에서 토큰·AST·IR 덤프 일치, 부정 테스트 15개 동일 판정 (`python build.py selfhost`). 헌장 원칙대로, 필요한 언어·라이브러리 기능은 명세와 테스트를 먼저 갖춘 뒤에 컴파일러 작성에 들어간다.

## 목표

글로 쓴 컴파일러 `self/`가 참조 구현 `ref/`와 **같은 수용 테스트를 통과하고, 같은 소스에 대해 같은 바이트의 exe를 낸다.** 참조 구현은 영구 부트스트랩으로 남는다 (D-04). 1세대처럼 자기 자신만이 자기를 빌드할 수 있는 상태는 만들지 않는다.

## 준비 상태 점검

| 컴파일러가 필요로 하는 것 | 상태 | 비고 |
|---|---|---|
| 파일 읽기, UTF-8 argv, 종료코드 | 있음 | `표준/입출력.gl`, D-07 시작 코드 |
| 늘어나는 배열 (토큰·노드·명령 풀) | 있음 | `표준/배열.gl` 동적배열 (원소 크기 지정, 범위 검사) |
| 정수 목록 | 있음 | `표준/목록.gl` |
| 문자열 조작 (자르기, 합치기, 서식) | 있음 | `표준/문자열.gl`, `버퍼에_쓰기` |
| 묶음·참조·함수 포인터·64비트 정수·비트 연산 | 있음 | 명세 3.3, 3.8 |
| 32비트 정수 (C 인터페이스, PE 헤더 필드) | 있음 | `중간정수` |
| 해시 테이블 (이름 → 심볼) | 있음 | `표준/사전.gl` — 문자열 키 → 정수 값, 개방 주소법 |
| 바이트 버퍼 (코드·데이터 섹션 조립) | 있음 | `표준/바이트열.gl` — 넣기(1·2·4·8바이트, 리틀엔디언)/고치기/파일로쓰기 |
| 파일 쓰기(바이너리) | 있음 | `파일_쓰기` |
| 묶음 값 대입·값 전달 | 없음(의도) | 참조로 다룬다. 필요해지면 D-05 추가 결정 |
| 오류 전파 | 없음(의도) | 컴파일러 오류는 메시지 후 `종료(1)`. D-03 종료코드 규약과 같다 |

## 구조

참조 구현의 모듈 경계를 그대로 옮긴다. 각 단계는 참조 구현과 **중간 결과를 비교**해 검증한다.

| 단계 | 글 소스 | 검증 방법 |
|---|---|---|
| 1. 렉서 | `self/렉서.gl` + `self/토큰덤프.gl` (완료) | `--dump-tokens` 출력을 참조 구현과 문자열 비교 — 113개 입력 일치 |
| 2. 파서 | `self/파서.gl` + `self/구문덤프.gl` (완료) | `--dump-ast` 비교 — 113개 입력 일치 |
| 3. 의미 분석 | `self/의미.gl` | 부정 테스트의 오류 메시지 일치 + `--dump-ir` 비교 |
| 4. IR 하강 | `self/하강.gl` | `--dump-ir` 비교 |
| 5. 코드 생성·PE | `self/x64.gl`, `self/pe.gl` | exe 바이트 동일 (교차 검증) |
| 6. 드라이버 | `self/컴파일러.gl` | 수용 테스트 전체 |

한 단계가 끝날 때마다 `build.py selfhost`가 (a) ref 로 self 를 빌드하고 (b) 그 self 로 수용 테스트를 돌리고 (c) 가능한 단계까지 덤프를 비교한다. 이 명령이 CI 에 들어간다.

## 규칙

- **부트스트랩 순서 규칙**: 표준 라이브러리·런타임이 새 외부 심볼을 쓰려면 먼저 `ref/`가 그것을 링크할 수 있어야 한다. 1세대 v0.7.0 의 순환(std 가 새 심볼을 써서 이전 컴파일러로 빌드 불가)을 재현하지 않는다.
- **덤프 형식은 명세다**: `--dump-tokens`, `--dump-ast`, `--dump-ir` 의 출력 형식을 문서로 고정하고 두 구현이 같은 형식을 낸다. 형식을 바꾸면 두 구현과 문서를 같이 바꾼다.
- **성능은 나중**: self 의 백엔드도 처음에는 ref 처럼 모든 임시값을 스택 슬롯에 둔다. 최적화는 두 구현이 바이트 동일한 뒤, 별도 결정으로 시작한다. 1세대 기준선(fib(40) 492 ms 등)은 그때의 목표다.
- **글 소스의 한계**: 자체호스팅 컴파일러를 쓰면서 언어에 불편한 점이 드러나면 우회하지 말고 결정 기록에 항목을 만든다. 1세대의 `(A) * (B) > 0` 관용구가 그 반대 사례다.

5. ~~`self/의미.gl` → 부정 테스트의 오류 메시지 일치 + `--dump-ir` 비교.~~ 완료 (타입 400줄, 의미 1,200줄, 하강 700줄). IR 덤프 형식을 `docs/05`에 고정했다. 이 단계에서 드러난 언어 문제: (a) `동적배열`이 늘어날 때 원소가 옮겨져 잡아 둔 참조가 무효가 된다 — 참조를 오래 드는 컴파일러 자료구조에는 맞지 않아 주소가 고정되는 `안정배열`을 표준에 추가했다; (b) 대입 `X→필드 = f(...)`에서 좌변 주소를 먼저 계산하므로 f 가 배열을 옮기면 옛 주소에 쓴다 — 평가 순서를 명세 3.4에 적어야 한다; (c) 절 중간의 변환 대상 타입 키워드(`x = y으로 실수.`)가 '문장 끝' 검사에 걸렸다 — 규칙을 고쳤다.
6. 다음: `self/x64.gl`(코드 생성) + `self/PE.gl`(실행 파일 쓰기) → 두 구현의 exe 바이트 동일 검증, 그다음 self 가 self 를 컴파일하는 고정점.
6. `build.py selfhost` 를 단계마다 확장하고 CI 에 넣는다.
