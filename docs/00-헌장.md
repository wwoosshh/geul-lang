# 글 2세대 헌장

이 문서는 2세대의 모든 결정보다 위에 있다. 아키텍처 결정이 이 문서와 충돌하면 결정을 바꾼다.

## 목표

1세대와 동일하다.

- 한글 키워드만으로 프로그램을 쓴다. 영어 함수명이 사용자 코드에 노출되지 않는다.
- 조사가 인자의 역할을 정한다. 인자 순서는 자유다.
- 외부 도구 없이 `.gl` → 네이티브 `.exe`.
- 컴파일러는 글로 쓰이고 자기 자신을 컴파일한다.

## 원칙 셋

### 1. 명세가 먼저다

문법과 의미는 코드가 아니라 명세 문서가 정의한다. 명세에 없는 것은 구현하지 않고, 구현되지 않은 것은 명세에 "미구현"이라고 적는다. README와 문법서는 명세에서 파생되며 명세와 다른 예제를 실을 수 없다.

토큰화는 결정적이어야 한다. 같은 글자열은 선언 순서, 심볼 테이블, 파서 상태와 무관하게 같은 토큰열이 되거나, 문맥에 따른 분리 규칙이 명세에 명시된다.

### 2. 실패는 시끄럽게

컴파일러는 틀린 프로그램을 만들지 않는다. 다음은 전부 오류이며 빌드를 중단하고 0이 아닌 종료코드를 낸다.

- 미선언 식별자, 타입 불일치, 인자 개수·역할 불일치
- 내부 한계 초과 (풀, 버퍼, 인코딩 범위)
- 미해결 참조, 출력 파일 쓰기 실패
- 처리하지 않는 옵션

"경고 후 계속"은 없다. 경고는 프로그램의 정확성과 무관한 문체 지적에만 쓴다.

### 3. 기능은 테스트와 함께

기능 하나의 완료 정의:

- 명세 항목이 있다.
- 참조 구현이 있다.
- 자기검증 수용 테스트가 있다 (기대 출력 + 기대 종료코드).
- 그 기능의 오류 메시지를 확인하는 부정 테스트가 있다.

네 가지 중 하나라도 없으면 기능은 없는 것이다. 테스트 러너는 컴파일 실패를 실패로 센다. 건너뜀은 없다.

## 보조 원칙

- **개념당 표기 하나.** 같은 의미를 두 문법으로 쓸 수 있게 하지 않는다. 입력하기 어려운 글자(`→`)의 순수 어휘적 별칭(`->`)만 예외로 허용하며, 별칭은 의미 차이가 0이어야 한다.
- **부트스트랩은 설계의 일부다.** 참조 구현은 자체호스팅 이후에도 삭제하지 않고 영구 부트스트랩으로 유지한다. 표준 라이브러리나 런타임 변경이 "새 컴파일러"를 요구하면 설계 오류다.
- **자체호스팅은 3단계 목표다.** 언어가 컴파일러 작성에 필요한 기능(동적 배열, 단락 논리 연산, 64비트 정수, 오류 전파)을 갖추기 전에는 시작하지 않는다.
- **텍스트는 UTF-8이다.** 소스, 명령줄 인자, 파일 경로, 콘솔 출력 모두 UTF-8이며 변환은 런타임 경계에서 한 번만 한다.
- **버전은 한 곳에서.** 버전 문자열은 `VERSION` 파일 하나에서 생성된다.
- **빌드는 한 경로로.** 클린 클론에서 문서에 적힌 명령 하나로 빌드된다. 저장소 밖 경로, 특정 머신의 설치 경로에 의존하지 않는다. CI가 매 커밋 이를 증명한다.

## 금지 목록

1세대에서 실제로 문제를 일으킨 것들이다. 코드 리뷰에서 발견되면 머지하지 않는다.

- 경계 검사 없는 고정 크기 배열·풀
- 오류를 출력하고 계속 진행하는 코드
- 문서에만 있고 파서에 없는 문법, 도움말에만 있고 처리되지 않는 옵션
- 심볼 테이블을 보고 토큰을 자르는 렉서
- 값의 타입을 IR 밖의 플래그로 추측하는 백엔드
- 사용자 프로그램에 사용자가 쓰지 않은 호출(`system("pause")` 같은 것)을 끼워 넣는 것
- 같은 파일의 사본을 여러 경로에 두는 것
- 결과가 종료코드에 반영되지 않는 테스트 러너

## 1세대에서 가져오는 것

- 언어 개념 전부 (조사 역할 바인딩, 동사형 호출, 보간, `.` 종결, 키워드 집합)
- PE 기록기와 x86-64 인코더 표 (검증된 부품. 레지스터 할당과 플래그 추측 로직은 가져오지 않는다)
- 예제·프로젝트·벤치마크와 감사에서 만든 재현 케이스 (수용 테스트 코퍼스)
