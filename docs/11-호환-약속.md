# 1.0 호환 약속

1.0 부터 글은 아래를 지킨다. 이 문서가 "무엇을 믿고 코드를 써도 되는가" 의 답이다.

## 1. 얼리는 것

1.x 안에서는 바꾸지 않는다. 바꾸려면 2.0 이고, 결정 기록(`02-설계결정-기록.md`)에 먼저 올린다.

| 얼리는 것 | 어디에 적혀 있는가 |
|---|---|
| 문법과 의미 | `03-문법-명세.md` |
| 표준 라이브러리의 **함수 이름, 매개변수 순서, 역할 조사, 반환 타입** | `06-표준-라이브러리.md` |
| 종료 코드 (0 성공, 1 오류, 2 내부 오류, 3 처리되지 않은 예외) | `00-헌장.md` |
| 명령줄 옵션 `-o`, `--check`, `--version`, `--dump-*` | `README.md` |
| 생성된 실행 파일이 `kernel32.dll` 과 `shell32.dll` 만 쓴다는 것 | |

**1.0 에서 도는 프로그램은 모든 1.x 에서 돈다.**

## 2. 더할 수 있는 것

더하기만 하는 변화는 1.x 에서 한다.

- 표준 라이브러리에 **새 함수와 새 모듈**. 기존 것은 지우지도 고치지도 않는다.
- 문법에 **더하는 규칙**. 지금 오류인 것을 받아들이게 만드는 것만 해당한다.
  1.0 까지의 D-34(범위 반복), D-35(보간에 식), D-37(접두어 생략)이 그런 예다.
- 새 명령줄 옵션.

## 3. 바뀔 수 있는 것

의지하면 안 되는 것들이다.

- **오류 메시지의 문구.** 줄·열은 정확하지만 문장은 나아질 수 있다. 다만 두 구현은 언제나
  글자까지 같은 메시지를 내며, `spec-tests/`의 부정 테스트가 그것을 고정한다.
- **생성된 기계어와 실행 파일의 바이트.** 최적화가 바꾼다. 프로그램의 **동작**은 안 바뀐다.
- **`--dump-*` 의 출력 형식.** 두 구현을 맞추는 데 쓰는 개발용 출력이다.
- **참조 구현(`ref/`)과 자체 컴파일러(`self/`)의 내부 구조.**
- **컴파일 속도와 실행 속도.** 빨라지는 쪽으로만.

## 4. 지금 없는 것 — 1.x 에서 생길 수도 있다

없다고 해서 나중에 안 생긴다는 뜻은 아니다. 생기더라도 위의 약속을 깨지 않는 방식으로 생긴다.

| 없는 것 | 왜 |
|---|---|
| 이름공간 | D-15. 접두어 규약으로 대신하고, 동사형에서는 D-37 이 그것을 생략한다 |
| 다른 운영체제 (리눅스 ELF) | 표준 라이브러리의 하부를 갈라야 한다 |
| 디버거용 예외 정보 (.pdata) | D-28 에 미룬 이유를 적었다 |
| 가변 인자 전달 | D-36. 받은 가변 인자를 다른 가변 함수로 넘길 수 없다 |
| 꾸러미 관리 | |

## 5. 무엇이 이 약속을 지키는가

말이 아니라 빌드가 지킨다. 매 커밋마다 이만큼이 돈다.

| 검증 | 무엇을 고정하는가 |
|---|---|
| 수용 테스트 (양쪽 구현) | 언어의 동작 |
| 부정 테스트 | 오류의 줄·열·문구가 두 구현에서 같음 |
| 덤프 교차 비교 (토큰·구문·IR) | 두 구현이 같은 언어를 구현함 |
| 실행 파일 바이트 비교 | 두 구현이 같은 기계어를 냄 |
| 자기 컴파일 고정점 | 글로 쓴 컴파일러가 자기 자신을 컴파일해도 같음 |
| 문서 예제 실행 | 문서에 적힌 것이 실제로 그렇게 돎 |

문서가 낡으면 빌드가 깨진다 (D-33).

## 6. 판 번호

`주.부.수` 를 쓴다.

- **수** — 고침만. 언어는 그대로다.
- **부** — 더하는 문법이나 새 표준 함수가 들어갔다. 옛 코드는 그대로 돈다.
- **주** — 위의 약속을 깨는 변화. 결정 기록에 근거를 남긴다.
