# 16. 작동 원리 — 소스에서 실행 파일까지

이 문서는 글 컴파일러가 어떻게 동작하는지를 처음 보는 사람에게 설명한다. 코드를 읽지 않고도 각 단계가 무엇을 하고 왜 그렇게 했는지 알 수 있게 쓴다. 파일 이름은 참조 구현(`ref/geul/`) 기준이고, 자체 컴파일러(`self/`)는 같은 구조를 글로 쓴 것이다.

## 0. 두 개의 구현이 있는 이유

컴파일러가 둘이다. **참조 구현**(파이썬, 6,858줄)은 문법 명세를 그대로 옮긴 것으로, 언어를 처음 만들 때의 기준이자 영구 부트스트랩이다. **자체 컴파일러**(글, 9,320줄)는 같은 단계를 글로 다시 쓴 것이다.

둘이 있어서 얻는 것은 **검증**이다. 어떤 프로그램을 두 컴파일러에 넣으면 토큰 목록, 구문 트리, 중간 표현, 기계어가 전부 같아야 한다. 하나만 있으면 "컴파일러가 맞게 동작하는가"를 컴파일러 자신으로만 확인해야 하지만, 둘이 있으면 서로가 서로를 검증한다. 언어를 바꿀 때는 두 구현을 함께 고치고, 갈라지는 지점을 덤프 비교가 잡는다.

## 1. 어휘 분석 (`lexer.py`, `self/렉서.gl`)

영어 언어의 어휘 분석은 공백과 기호로 토큰을 나누면 끝나지만, 한국어에는 **조사가 단어에 붙어 있다**는 문제가 있다. `원본을`은 `원본`이라는 이름과 `을`이라는 조사다. 그런데 `기본을`은 `기본`+`을`이고, `마을을`은 `마을`+`을`이지 `마`+`을을`이 아니다.

글의 규칙(명세 2.4): **인자 위치의 단어는 끝에서 가장 긴 조사를 뗀다.** 어디가 인자 위치인지는 파서가 안다(SOV 문장의 인자, 조건의 `X이/가 Y보다`). 그래서 어휘 분석기는 단어를 통째로 토큰으로 내고, 파서가 인자 자리에서만 조사를 분리한다 — 상태 의존 토큰화(1세대의 결함 하나)를 피하는 설계다. 예외가 둘 있다: 단어에 `(`나 `[`가 공백 없이 붙어 있으면 호출·색인이므로 나누지 않고(`파일_끝인가(f)를`), `의`는 항상 분리한다(멤버 접근이 너무 흔해서; 그래서 `의`로 끝나는 이름은 선언할 수 없다).

한글 정규화도 여기서 검사한다. 같은 글자를 완성형(NFC)과 결합 자모로 두 가지 바이트열로 쓸 수 있는데, 컴파일러가 조용히 정규화하면 이름 비교가 어긋나는 것을 숨기게 되므로, 결합 자모가 나오면 오류다.

## 2. 구문 분석 (`parser.py`, `self/파서.gl`)

한국어 문장은 동사가 끝에 온다. `원본을 대상에 복사하다.`는 인자들 뒤에 동사형 호출이 온다. 파서는 문장을 토큰 범위로 잘라, 끝 단어가 `-하다` 꼴이면 SOV 호출로 읽고 앞의 단어들을 `(식, 역할)` 목록으로 만든다 — 각 단어 끝에서 조사를 떼어 역할로 삼는다. `쓰다`처럼 동사형은 `쓰기`라는 함수 이름의 활용이며, 접두어가 있는 표준 함수(`정수목록_추가`)도 `추가하다`로 부를 수 있게 인자의 선언 타입으로 접두어를 고른다(D-37).

식은 우선순위 오르기(또는 < 그리고 < 비트 < 비교 < 시프트 < 덧셈 < 곱셈 < 단항)로 파싱한다. 변환은 후위 `식으로 타입`이다. `크기(타입)`, `시도 식`, `교체(함수, 식)`는 키워드 형식이다.

파서가 **펴는** 문법이 둘 있다. 범위 반복 `(정수 i는 0부터 n 전까지)`는 세 절 반복(`i = 0: i < n: i += 1`)으로, 문자열 보간 `"{a + b}"`는 서식 문자열과 인자 목록으로 펴진다. 그래서 의미 분석 이하는 이 문법을 모른다 — 표기만 더하고 나머지 단계는 그대로인 방식이다(D-34·35).

## 3. 의미 분석 (`sema.py`, `self/의미.gl`)

이름을 심볼(변수·함수·상수·타입)에 묶고, 모든 식의 타입을 정하고, 변환을 넣고, 오류를 낸다. 세 가지가 특별하다.

**변환 규칙은 좁다.** 정수끼리는 암시 변환(넓히기는 부호에 따라 확장, 좁히기는 절단, 리터럴이 범위를 넘으면 오류), 공허 참조는 모든 참조와 양방향, 배열은 참조·조각으로. 그 밖은 `으로` 명시 변환이어야 한다. 정수→실수도 명시다. 계산된 주소를 함수로 쓰는 것은 명명 함수 타입으로의 명시 변환만 허용한다(D-41).

**방향 안전성 검사(D-30).** 함수를 검사할 때 매개변수 중 같은 타입이면서 역할(조사)이 다른 짝을 찾아 둔다. 호출부에서 그 두 자리에 조사가 하나도 안 붙었으면 오류다 — 자리를 바꿔 써도 컴파일되는 호출이기 때문이다. 같은 타입·같은 역할인 짝은 격으로 구별할 수 없으므로 언어가 구별하지 않고(D-32), 도구 `--dump-risky`가 알려 준다.

**제네릭은 단형화다(D-19).** `묶음 목록(T)`나 `[T 참조 x를 ... 이름(T)]`는 틀로 두고, 실제 타입으로 쓰인 자리마다 구문 트리를 복제해 타입을 묶어 검사한다. 인스턴스는 첫 사용 순서로 이름이 정해지므로 두 구현이 같은 순서를 낸다.

## 4. 타입 IR과 하강 (`ir.py`, `lower.py`, `self/하강.gl`)

구문 트리를 **타입이 붙은 비SSA 중간 표현**으로 내린다. 함수마다 임시값(`%3: 정수`)과 라벨, 그리고 `상수·복사·적재·저장·원소주소·이항·비교·변환·호출·분기·반환` 같은 명령의 목록이다. SSA를 쓰지 않은 것은 1세대의 "타입 없는 IR"을 고치는 데 필요한 최소가 타입 부착이었고, 백엔드의 핍홀이 단일 사용 임시값을 직접 다루면 충분했기 때문이다.

이 단계에서 언어의 안전 장치가 **명시적 명령**이 된다. 조각 색인 `s[i]`는 `0 ≤ i < 길이` 비교와 실패 시 `__글_범위오류` 호출로 펴진다. 결과 타입 `T 결과`의 `시도 r`은 오류 코드 검사와 이른 반환으로 펴진다. 묶음 값 전달(D-16)은 숨은 결과 매개변수와 `복사메모리` 명령이 된다. 전역 문자열 초기값은 문자열 풀 순서를 결정적으로 정하기 위해 함수 본문보다 먼저 등록된다 — 재현 가능한 빌드의 조건 중 하나다.

이어서 **인라인**(`inline.py`, D-31)이 작은 함수(라벨 뺀 본문 12명령 이하, 분기 없음, 반환 하나, 집합체 없음, 비재귀)를 호출 자리에 한 겹 편다. 상수 접기·죽은 코드 제거는 재 보니 값이 없어서 안 한다(컴파일러 IR 7만 명령에서 접을 상수 4개).

## 5. 코드 생성 (`codegen.py`, `self/코드생성.gl`)

함수 하나씩, 세 단계로 기계어를 낸다.

**분석(핍홀, D-12).** 한 번만 정의되고 한 번만 쓰이는 상수는 명령을 내지 않고 사용처의 즉시값으로 접는다. 적재·저장의 주소로만 쓰이는 오프셋·원소주소는 메모리 피연산자에 접는다. 비교가 바로 분기의 조건이면 `setcc` 없이 `jcc`로 잇는다.

**레지스터 할당(D-20).** 선형 스캔이다. 정수·참조 값은 피호출자 보존 레지스터 일곱 개(RBX·RSI·RDI·R12~R15)에, 실수는 XMM6~XMM15에 배정한다. 임시값이 RAX로만 흐르면 슬롯 없이 전달한다("RAX 전달"). 생존 구간은 블록 경계·정의·사용 위치를 모두 포함해 보수적으로 잡는다. 벤치마크에서 루프가 0.45→0.26초, 실수 연산이 1.22→0.74초로 줄었고, 두 구현이 여전히 바이트 동일했다.

**방출.** Win64 호출 규약을 따른다 — 처음 네 인자는 RCX·RDX·R8·R9(실수는 XMM0~3), 다섯째부터 스택, 호출자가 32바이트 그림자 공간을 둔다. 호출은 네 꼴이다: 내부 함수는 `call rel32`, 외부 함수는 IAT를 거치는 `call [rip+disp]`, 함수 포인터는 `call 레지스터`, 그리고 `--핫스왑`이면 내부 함수도 함수 테이블을 거치는 `call [rip+슬롯]`이다.

## 6. x86-64 인코더 (`x64.py`, `self/x64.gl`)

필요한 명령만, 항상 명시적으로 인코딩한다. REX 접두사·ModRM·SIB를 직접 조립하고, 메모리 피연산자는 `[베이스+disp32]` 또는 `[rip+disp32]` 두 꼴만 쓴다. 코드 안의 상대 주소(분기·내부 호출)는 라벨 고정으로, 코드 밖(IAT·문자열·전역·함수 테이블)은 RIP 상대 고정으로 남겨 뒀다가 배치가 끝난 뒤 채운다. SSE로 실수를 다룬다(`movsd`·`addsd`·`cvtsi2sd`…).

## 7. PE32+ 기록 (`pe.py`, `self/PE.gl`)

섹션 셋을 만든다. `.text`(코드), `.rdata`(문자열 풀 + 임포트 디렉터리·ILT·IAT·이름 테이블), `.data`(전역 변수, 함수 테이블). 이미지 베이스는 `0x140000000`으로 고정하고 재배치 테이블을 두지 않는다 — 코드는 전부 RIP 상대라 재배치가 필요 없고, 데이터 안의 절대 주소(전역 문자열 포인터, 함수 테이블 슬롯)는 고정 베이스로 링크 때 계산한다. 타임스탬프는 0이다. 그래서 같은 소스는 언제나 같은 바이트다.

임포트는 사용한 심볼만 DLL별로 모은다. 기본 목록(kernel32·shell32) 밖의 DLL은 외부 선언에 이름을 적는다(D-38). 서브시스템은 콘솔(3) 또는 창(2)이다(D-39).

## 8. 런타임 — C 런타임 없이 (`runtime.py`, `표준/`)

프로그램의 시작 코드는 컴파일러가 **IR로 생성**해 같은 백엔드로 낸다(D-07). 하는 일: 벡터 예외 처리기 설치(아는 치명적 예외만 잡는다, D-40), 콘솔 출력 코드페이지를 저장하고 UTF-8로 바꿈, `GetCommandLineW`→`CommandLineToArgvW`→UTF-8 변환으로 `argv`를 만듦, `시작하기` 호출, 출력 버퍼 비움, 코드페이지 복원, `ExitProcess`.

표준 라이브러리(2,761줄)는 전부 kernel32 위에 글로 썼다: 힙(`HeapAlloc`), 문자열, 서식 출력(`%d %s %f %c %x %e %g`를 직접 구현 — 실수 변환은 파이썬과 비트 일치), 파일·디렉터리(`CreateFileW`·`FindFirstFileW`), 시간, 명령 실행, 정렬(힙 정렬), 사전(해시), 동적배열·안정배열, 조각·결과 지원 함수. 그래서 실행 파일은 `msvcrt`를 임포트하지 않는다.

## 9. 자체호스팅 부트스트랩 (`build.py selfhost`)

자체 컴파일러는 참조 구현이 완성된 **뒤에**, 단계별로 만들었다(D-04, 1세대의 "너무 이른 자체호스팅"을 고친 것). 각 단계마다 교차 검증이 있다:

1. `토큰덤프` — 두 구현의 토큰 목록이 194개 입력 전부에서 같은가.
2. `구문덤프` — 구문 트리 덤프가 같은가.
3. `IR덤프` — 타입 IR 덤프가 같은가.
4. `컴파일러` — 참조 구현이 `self/컴파일러.gl`로 1세대 `geulc.exe`를 만들고, 그 1세대가 자기 소스로 2세대를, 2세대가 3세대를 만든다. **세 세대의 바이트가 같으면 고정점**이다. 또 모든 통과 테스트를 참조 구현과 글 컴파일러로 각각 컴파일해 실행 파일 바이트를 비교하고, 호출 색인과 위험 보고도 비교한다.

규칙 셋: 참조 구현은 영구 부트스트랩이다(자체 컴파일러가 참조 구현을 대체하지 않는다), 언어를 바꾸면 두 구현을 함께 고친다, 대량 기계 변환은 반드시 바이트 비교로 검증한다(실제로 서식 자리 너비·부호·복합 조건의 오독 세 건을 이 비교가 잡았다).

## 10. 실행 중 함수 교체 (1.2.0)

세 조각이 합쳐진다.

- **함수 테이블(`--핫스왑`, D-42).** 함수마다 8바이트 슬롯을 `.data`에 두고 함수의 절대 주소로 채운다. 내부 호출을 `call [rip+슬롯]`으로 낸다 — 외부 함수가 IAT를 거치는 것과 같은 구조다. 플래그가 꺼지면 이전과 바이트가 같다.
- **교체(D-43).** `교체(함수, 새주소)`는 그 함수의 슬롯 주소를 `lea`로 얻어(호출과 같은 고정) 새 주소를 써 넣는다. 다음 호출부터 새 코드로 간다. 인라인은 끈다 — 인라인된 호출은 테이블을 안 거치기 때문이다.
- **새 코드(D-41·44).** 실행 중 프로그램이 `VirtualAlloc`으로 메모리를 잡아 기계어를 쓰고(W^X: 쓸 때 RW, 실행 때 RX) 명시 변환으로 함수로 삼는다. `--조각`은 순수 잎 함수 하나를 위치 독립 원시 코드 파일로 내서, 호스트가 읽어 넣을 수 있게 한다.

결과: 실행 중인 프로그램의 전역·힙·현재 데이터는 그대로이고 함수 본문만 바뀐다. 콘솔 생명 게임에서 살아있는 패턴이 규칙만 바뀐 채 이어지는 것, 요금 튜닝기에서 300건 데이터를 든 채 요금 규칙만 갈리는 것을 확인했다.

## 11. 원칙이 구현에 나타나는 자리

- **오류만, 경고 없음** — 컴파일러에 경고 채널이 없다. 위험 보고는 오류로 승격하거나(D-30) 도구 출력으로 뺀다(`--dump-risky`).
- **조용한 실패 없음** — 고정 풀은 크기를 검사하고, 모르는 예외는 넘기되 아는 치명적 예외는 진단을 찍고 죽는다.
- **문서에만 있는 문법 없음** — 입문서의 모든 예제를 빌드 때 컴파일·실행해 결과와 맞춘다(D-33). 문서가 낡으면 빌드가 깨진다.
- **결정은 기록한다** — 설계 결정 D-01~D-45가 근거·비용·대가와 함께 있고, 방향의 중단과 완성도 같은 형식으로 남겼다.
