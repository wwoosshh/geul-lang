# 읽기 쉬움 점검 — 글은 정말 읽기 쉬운가

작성 2026-09-04, 1.0.0-rc5 시점.

"글로 사람이 실제로 코딩할 때 영어 기반 언어보다 읽기 쉬운가" 를 재 봤다. **아직 아니다.**
이 문서는 왜 아닌지를 숫자로 밝히고, 무엇을 고치면 되는지를 고른다.

---

## 1. 측정

저장소의 모든 글 코드를 두 무리로 나눠 셌다.

| | 컴파일러 + 표준 (10,521줄) | 응용·예제 (2,245줄) |
|---|---|---|
| 동사형 호출 | 244 (3.6%) | 298 (52.9%) |
| 괄호 호출 | 6,503 (96.4%) | 265 (47.1%) |
| 괄호 호출 중 식 자리 | 67% | 45% |
| 한국어 문법으로 읽히는 줄 | 863 (8%) | 467 (21%) |
| 기계 표기 줄 | 4,930 (47%) | 257 (11%) |

**진짜 규모의 코드에서는 열 줄에 한 줄도 한국어로 읽히지 않는다.** 예제는 21% 지만 이것은
동사형을 보여주려고 쓴 예제라서 그렇다. 컴파일러가 정직한 표본이다.

## 2. 왜 그런가 — 어색함은 세 곳에 몰려 있다

어느 프로그램에나 가장 많이 나오는 세 가지가 정확히 셋 다 한국어가 아니다.

### 2.1 반복문 (357개 중 339개, 95%)

```
반복 (정수 i = 0: i < 단어수: i += 1) {
```

C 의 `for` 를 콜론으로 바꾼 것이다. 한국어가 한 글자도 없다. 속내용을 세어 보면
235개가 `0부터 n 앞까지`, 64개가 `그릇의 길이만큼`, 10개가 `a부터 b까지` 다.
**즉 95% 가 "어디부터 어디까지" 하나로 적을 수 있는 모양이다.**

### 2.2 출력 (쓰기 호출 483개 중 333개, 69%)

```
"%2lld. %s (%lld)\n"을 (r + 1)을 단어들[r]을 횟수들[r]을 쓰다.
```

한 문장에 `을/를` 이 넷이다. 한국어는 한 절에 목적어를 하나만 둔다. 게다가 맨 앞에
`%2lld` 같은 C 서식이 온다. 한국어로 프로그래밍을 배우려는 사람이 가장 먼저 만나는 줄이
하필 C 서식 문자열이다.

문자열 보간이 이미 있는데 **저장소 전체에서 11곳만 쓴다.** 이유를 시험해 봤다.

| 보간 안에 넣은 것 | 결과 |
|---|---|
| `{이름}` | 됨 |
| `{a + b}` | 오류 — 보간에 쓸 수 없는 이름 |
| `{두배(a)}` | 오류 |
| `{p의 x}` | 오류 |

**이름 하나만 된다.** 그래서 아무도 안 쓴다.

### 2.3 라이브러리 이름 (표준 함수 234개 중 172개, 74%)

선언은 이미 한국어다.

```
[사전 참조 d에 문자열 키를 정수 값을 사전_넣기]는 {
```

그런데 이름이 `사전_넣기` 라서 동사형으로 부르면 `사전_넣다` 가 된다. 부를 수 없는 동사다.
그래서 전부 괄호로 부른다 — `사전_넣기(빈도, 단어, 1)`. **언어의 간판 기능이 자기
표준 라이브러리에서는 쓰이지 못한다.**

## 3. 공정하게 볼 것 — 고칠 수 없는 부분

전부가 언어 탓은 아니다. 나머지 큰 덩어리는 **식 자리의 호출**이다.

```
문자열 k = 사전_자리키(빈도, s).
```

동사형은 괄호를 씌우면 식에서도 된다 (`정수 v = (3에 4를 더하다).` 는 돌아간다). 하지만
값을 다른 계산에 흘려보내는 자리에서는 어느 언어도 산문으로 읽히지 않는다. 자바로 써도
`String k = freq.keyAt(s);` 이고 이것도 영어 문장이 아니다. 더 나쁜 것은 중첩이다.

```
빈도에 단어를 (빈도에서 단어를 0으로 값보다) + 1을 넣다.      (* 동사형 *)
사전_넣기(빈도, 단어, 사전_값_기본(빈도, 단어, 0) + 1).       (* 괄호 *)
```

동사형 쪽이 **더** 읽기 어렵다. 한국어는 절을 값으로 끼워 넣는 방법이 없어서 (관형형이나
명사형으로 바꿔야 한다) 괄호가 이물질로 남는다. 이것은 SOV 언어의 구조적 성질이지 설계
실수가 아니다.

**그러므로 목표는 "모든 줄이 한국어" 가 아니다. 문장 자리에서 한국어가 되게 하고, 식
자리에서는 짧고 규칙적이면 된다.** 지금 문제는 문장 자리조차 한국어가 아니라는 것이다.

## 4. 고칠 것 — 빈도 × 이득 ÷ 비용 순

### 제안 A — 범위 반복 (더하는 문법, 기존 형태 유지)

```
반복 (정수 i는 0부터 단어수 전까지) { }     (* 0, 1, …, 단어수-1 *)
반복 (정수 i는 1부터 9까지) { }            (* 1, …, 9 *)
```

`전까지` 와 `까지` 는 한국어 그대로다. 반복문 95% 를 덮는다. 남은 5% (거꾸로, 두 칸씩)는
지금의 세 절 형태를 그대로 쓴다. 순전히 더하는 문법이라 기존 코드가 깨지지 않는다.

### 제안 B — 보간 안에 식 허용

```
"{r + 1}. {단어들[r]} ({횟수들[r]})\n"을 쓰다.
```

`을/를` 이 하나로 준다. C 서식 문자열이 사라진다. 출력문 69% 를 덮고, 입문자가 만나는
첫 줄이 바뀐다. 역시 더하는 문법이다.

### 제안 C — 표준 라이브러리 짧은 이름

`사전_넣기` 를 `넣기` 로 줄이면 `빈도에 단어를 1을 넣다` 가 된다. 다만 이름이 겹친다.
234개 이름의 밑줄 뒤를 잘라 세어 봤다.

| | 개수 |
|---|---|
| 겹치는 무리 | 32개 (함수 87개) |
| 받는 인자 타입으로 구별됨 | 25무리 |
| 구별 안 됨 | 7무리 (`만들기`, `자르기`, `찾기`, `변환` 등) |

25무리는 풀리고 7무리는 안 풀린다. 그리고 3장에서 봤듯이 **이득은 문장 자리에만 생긴다**.
`사전_용량(빈도)` 가 `용량(빈도)` 가 되는 것은 짧아질 뿐 한국어가 되는 것은 아니다.
비용은 이름 겹침 해소를 의미 검사에 넣는 일이라 A·B 보다 훨씬 크다.

### 제안 D — 이어 쓰기 (연구 과제)

한국어는 중첩이 아니라 연결어미로 잇는다. "잘라서 넣다", "세어서 보이다". 3장의 중첩
문제를 정면으로 푸는 길이지만 설계가 열려 있다. 지금 정할 것이 아니다.

## 5. 제안

**A 와 B 를 하고, C 는 미루고, D 는 적어만 둔다.**

A 와 B 는 둘 다 더하는 문법이라 기존 코드가 그대로 돌아가고, 둘이서 프로그램에서 가장
자주 나오는 두 줄 모양을 C 표기에서 한국어로 옮긴다. C 는 이득이 문장 자리에 한정되는데
비용은 의미 검사를 건드리는 일이다. 1.0 을 얼리기 전에 할 일로는 A·B 가 맞다.

## 6. 한 것과 그것이 산 것

A 와 B 를 넣었다 (D-34, D-35). 둘 다 더하는 문법이라 기존 코드는 한 줄도 고치지 않아도 돈다.

입문서(`09-입문.md`)의 예제 전부를 새 표기로 옮겨 재 봤다. 예제는 빌드가 컴파일·실행해 출력을
맞추므로, 옮긴 것이 같은 프로그램이라는 것은 기계가 확인한다.

| | 고치기 전 | 고친 뒤 |
|---|---|---|
| C 서식 문자열이 있는 줄 | 38 | 11 |
| C 꼴 세 절 반복문 | 14 | 1 |
| 한국어 문법으로 읽히는 줄 | 15% | 17% |
| 기계 표기 줄 | 25% | 22% |

**겨눈 두 가지는 거의 사라졌고, 전체 비율은 조금밖에 안 움직였다.** 3장에서 예고한 그대로다.
남은 줄의 대부분은 선언, 대입, 그리고 값을 다른 계산으로 흘려보내는 식 자리의 호출이며 이것들은
어느 언어에서도 산문이 아니다. 이 숫자를 더 올리려면 3장의 구조적 문제(제안 D)를 풀어야 한다.

남은 서식 문자열 11줄은 두 가지 이유다.

- **실수.** 보간은 실수에 `%f` 를 골라 `172.500000` 이 된다. `%g` 의 `172.5` 가 필요하면 서식을 쓴다.
- **문자열 리터럴.** `{문자열_길이("가나")}` 는 못 쓴다. 따옴표가 바깥 문자열을 먼저 끝낸다.

둘 다 고칠 수 있지만 값과 비용을 따로 재야 한다. 실수 서식을 `%g` 로 바꾸는 것은 이미 나간
동작을 바꾸는 일이고, 중괄호 안의 따옴표를 살리려면 렉서가 문자열 안에서 중괄호 깊이를 세야 한다.

## 7. 남은 것

- **제안 C (짧은 이름).** 이득이 문장 자리에 한정되고 비용은 의미 검사를 건드린다. 미룬다.
- **제안 D (이어 쓰기).** 중첩을 연결어미로 푸는 길. 설계가 열려 있다. 연구 과제로 남긴다.
- **보간의 실수 서식과 문자열 리터럴.** 위의 두 가지.
