# 12. 시장조사 — 어디에 부족이 있는가

조사일 2026-09-04~05. 질문은 하나였다. **"수요는 있는데 공급이 모자란 곳이 어디인가, 그리고 글이 그 자리에 맞는가."**
방법은 공개 자료(통계·논문·기사·경쟁 제품·저장소) 검색과 직접 측정(09장 성능)이다. 사용자 인터뷰는 하지 않았다. 그래서 이 문서는 "어디를 파야 하는가"까지만 말하고, "판다면 나오는가"는 §8의 실험으로 넘긴다.

---

## 0. 결론 먼저

1. 수요가 자라고 있고, 공급이 문서로 확인될 만큼 부족하며, 모국어 언어가 실제로 자리 잡은 선례가 있는 시장은 **하나**뿐이다: **초등 고학년~중학교의 블록 코딩 → 텍스트 코딩 전환 단계.**
2. 그러나 그 자리는 **비어 있지 않다.** 엔트리 파이썬(네이버, 무료, 시장 지배 플랫폼 내장), 호랑(2023년 창업, 학교 영업 중), Hedy(국제 오픈소스, 월 50만 명)가 이미 있다.
3. 실제로 비어 있는 것은 "한글 텍스트 언어"가 아니라 **그 언어를 둘러싼 것들**이다 — 교사(중학교 절반에 정보교사 없음), 엔트리 다음 단계의 교재, Hedy의 한국어 키워드(13/64), 그리고 **"모국어 키워드가 실제로 학습을 돕는가"에 대한 한국어 실증 데이터**(없음).
4. 지금의 글(데스크톱 컴파일러, exe, Win32)은 이 시장의 요구(브라우저, 무설치, 교사 자료, LMS)와 **거의 직교**한다. 2세대에서 만든 자산 중 이 시장에서 쓸 수 있는 것은 **언어 설계(조사·어순) 하나**다. 컴파일러·자체호스팅·성능은 여기서 가치가 0이다.
5. 교육 외의 후보(임베디드·시스템·서버·그래픽·안전필수·사무 자동화·성인 비전공 입문)는 모두 **"부족이 언어에 있지 않다"**로 판정됐다.

## 2. 공교육 시장 — 수요 근거

- **정책**: 2022 개정 교육과정으로 2025년부터 초등 정보 34시간, 중학교 68시간 이상(2배). 2025년 중학생 **1,370,356명**, 중학교 **3,292교**, 초등학생 2,345,488명 (2025 교육기본통계).
- **교사 부족**: 중학교 정보교사 배치율 **47.6%**(1,510교, 1,612명). 1명 이상 배치된 중학교 1,587/3,214(49.4%). 강원 21.0%·전북 23.9%·전남 27.8%. 교사 1명이 2~8개 학교 순회, 기간제가 대체. 양성 정원 연 500명 수준.
- **교과서**: 2015 개정 중학 정보 교과서 **15종 중 14종이 엔트리**(1종 스크래치). 2022 개정 검정 통과 8개사(교학사·비상·금성·미래엔·동아·천재·씨마스·이오북스). 교육과정은 초·중은 블록/텍스트 자유, 고교는 텍스트 필수.
- **전환 문제의 실재**: 엔트리 편중이 "교사 편의성 우선"으로 비판됨(에듀진). KISTI 2017 논문: 텍스트 언어 첫 접촉 시 "문법의 어려움과 외국어의 벽"이 확인되며 한글 언어를 중간 단계로 제안. 엔트리 파이썬 논문(초등 대상)은 효과를 주장하나 수치 미공개.

수요 판정: **정책이 강제한 시간은 2배가 됐고, 가르칠 사람은 절반이다.** 이것이 "부족"의 실체다. 단, 부족한 것은 **사람**이지 언어가 아니다 — 언어는 사람을 대체하지 못하지만, 교사 없는 학교가 쓰는 자료·도구 시장은 이 부족에서 생긴다.

## 3. 공급 지도 — 이미 그 자리에 있는 것들

### 3.1 엔트리 파이썬 (네이버 커넥트재단, 무료)
블록 ↔ 텍스트 상호 변환. 실제 코드(깃허브에 올라온 수업 파일):

```python
import Entry

def when_start():
    Entry.print("Hello World")
    Entry.input("숫자를 입력: ")
    son = Entry.answer()
    if ((son % 2) == 0):
        Entry.print("짝수")
```

- **정체**: 파이썬 문법 + 영어 API. 한국어는 문자열뿐. 즉 "블록→파이썬 다리"이지 "한국어 텍스트 언어"가 아니다.
- **한계**: 나무위키 기준 함수 호출 약 1,500회에서 튕김. 엔트리 세계 밖(파일·시스템)으로 못 나감.
- **위치**: 교과서 14/15종을 쥔 플랫폼에 내장. 무료. 교사에게 완성된 교안 제공.

### 3.2 호랑 (호랑에듀, 2023-06 창업)
- 자체 "한글 프로그래밍 언어" + AI 튜터 + LMS + 실시간 형성평가. **문법은 공개 자료 어디에도 없다**(사이트·기사·블로그 모두 코드 예시 없음).
- 시드 투자(윤민창의투자재단, 2024-05, 금액 비공개), 직원 7명, 한양대 창업보육센터.
- 실적: 자사 페이지 "340개+ 학교 선택"; 기사 기준 교육부 에듀테크 소프트랩 **30여 교 500여 명**. 2024 충북교육청·교원대 실증 "공교육 적합성 93.6점". KERIS 우수, 우수특허대상, HolonIQ 동아시아 150. 2025 한국컴퓨터교육학회 동계 논문(유도희·장윤재, 피지컬 컴퓨팅 교육 프로그램 개발).
- 포지셔닝 문구가 글의 결론과 **한 글자도 다르지 않다**: "블록코딩과 파이썬 사이의 징검다리."

### 3.3 Hedy (Felienne Hermans, 오픈소스, 2020~)
- 점진적 언어(레벨 1~18). 브라우저에서 실행, 무설치. 월 사용자 약 50만(2024). UI 47~54개 언어.
- **키워드 번역**이 핵심 기능인데, 저장소(`hedyorg/hedylang`, `src/hedy/data/keywords/`) 기준 번역 항목 수: **영어 64 · 일본어 59 · 중국어 63 · 한국어 13.** 한국어 파일 전체:
  `add: 추가하다, and: 그리고, ask: 묻다, at: 에서, black: 검정, blue: 파랑, brown: 갈색, call: 부르다, clear: 비우다, color: 색상, comma, d0, d1`
  즉 `print`조차 번역되지 않았다. 한국어 사용자는 사실상 영어 키워드 Hedy를 쓴다. **이것이 이번 조사에서 발견한 가장 구체적인 "빈 자리"다** — 그러나 그 빈 자리를 채우는 데 새 언어는 필요 없다. yaml 51줄이면 된다.

### 3.4 선례 — 성공 둘, 실패 여럿
- **なでしこ**(일본, 2005~, 1인 개발, 未踏ユース 2004, v3 MIT). 2021년 教育図書 중학교 技術 교과서에 채택. 정보처리학회 해설의 포지셔닝: "Scratch와 본격 언어 사이의 쿠션". 조사(助詞)로 토큰을 나누는 설계 — 글과 같은 발상. 사용층은 학생이 아니라 **30~40대 업무 자동화**였고, 교과서 채택은 그 15년 위에 얹힌 것이다. 教育図書의 技術 점유율은 유료 자료라 미확인(東京書籍 1위).
- **易语言**(중국, 2000~). 네이티브 컴파일, "수백만" 사용자. 쇠퇴 이유: x64·크로스플랫폼 부재, 작은 생태계, 게임 핵·악성코드 오명, 2000년 아키텍처. **모국어 컴파일 언어가 수백만에 닿을 수 있다는 것과, 그래도 죽을 수 있다는 것을 동시에 증명.**
- **한국**: 씨앗(1994, "한글 빼면 C" — 교육용으론 어렵고 호환 안 됨), 약속(2015), 하랑(고교생 앱), 두리틀·한플·말씨·숨, 한글코딩.org("공개하면 반응 있을 줄 알았다" — 없었다). 공통 사인: **한글 말고 다른 장점이 없었다**(나무위키 판정). KISTI 2017 논문의 한계 지적: 주류 언어로의 전이 제한, 자료·커뮤니티 부재, GUI·설치 불편.
- 2025~26 신생: Rust로 만든 'Han', UniversalPython(우르두어, 효과 측정 없음). 시장이 아니라 취미의 신호.

## 4. "모국어 키워드가 학습을 돕는가" — 연구는 갈린다

| 연구 | 규모 | 결과 | 글에 주는 함의 |
|---|---|---|---|
| Guo, CHI 2018 | 840명, 86개국 | 96%가 영어 자료로 학습. **키워드가 영어인 언어에서는** 번역 자료보다 영어 자료 선호(섞이면 혼란). 요청: 쉬운 영어, 시각 자료, 인라인 사전 | "영어 키워드 + 한국어 설명"이 나쁘다는 것이지 한국어 키워드 언어를 기각한 게 아님. 단, 학습자 스스로 원한 것은 모국어 언어가 아니었다 |
| Dasgupta & Hill, L@S 2017 | Scratch 15,000+명, 5개국 | 현지화 인터페이스 사용자가 블록 레퍼토리를 **더 빨리** 늘림 | 블록 환경·유럽어 한정. 저자 스스로 "limited and incomplete" |
| Hidden Burden of Keywords, 2026 | 27명(EAL 15/ENL 12), 6주 파이썬 | 키워드 식별 정확도 39.8→48.2%, 분류 40% 정체, 외재적 인지부하 **증가**(p=.039, d=.99) | 영어 키워드가 실제 부담이라는 근거. 표본 27 |
| Java 오류 메시지·모국어 수업 연구 | — | 모국어 수업이 만족도는 올리나 **성취도 차이 없음** | 만족도 ≠ 학습 |
| 한국어 실증 | 없음 | 호랑 "적합성 93.6점"은 학습 효과가 아니라 공교육 적합성 지표 | **한국어 텍스트 언어의 학습 효과 데이터는 존재하지 않는다** |

정직한 요약: **"모국어가 낫다"는 교육학의 일반 명제는 있으나, "한국어 키워드 텍스트 언어가 엔트리 파이썬보다 낫다"는 증거는 아무도 만든 적이 없다.** 이것이 시장의 빈 자리이자, 동시에 글이 그 시장에 들어갈 자격이 아직 없다는 뜻이다.

## 5. 반대 증거 — 들어가지 말아야 할 이유

1. **자리가 이미 셋으로 차 있다** (§3). 그중 둘은 무료다.
2. **한국 선례 전멸.** 한글 키워드만으로는 안 된다는 것이 30년간 반복 확인됐다.
3. **LLM 시대의 불이익.** 코드 LLM은 저자원 언어에서 성능이 크게 떨어진다(MultiPL-E 등). 신생 언어는 "무자원 언어"라 AI 보조가 거의 안 된다. 2026년 학습자는 AI에게 묻는다 — 파이썬은 답을 얻고 글은 못 얻는다. 완화 기법(문서 주입·미세조정)은 있으나 비용이 든다.
4. **교사 부족은 도구로 못 푼다.** 도구는 교사가 있는 학교에서 팔린다. 교사 없는 학교는 도구도 못 고른다.
5. **글의 현재 형태가 어긋난다.** 학교 환경: 크롬북·태블릿·설치 금지·교사 대시보드. 글: Windows exe 컴파일러. 09장의 성능(C 대비 2×, 43KB exe, 10ms 시작)은 이 시장에서 **아무 의미가 없다.**

## 6. 글이 그 자리에 맞는가 — 자산 대조

| 글의 자산 | 교육 시장 가치 | 비고 |
|---|---|---|
| 조사 기반 한국어 어순 (`"안녕\n"을 쓰다.`, `근속월 < 12이면 { … }`) | **유일한 차별점** | Hedy는 영어 어순에 단어만 치환(`묻다 이름?`). 호랑은 비공개. 엔트리 파이썬은 영어 |
| 자체호스팅 컴파일러 | 0 | 학생·교사 누구도 신경 안 씀 |
| 네이티브 exe, Win32 GUI | 거의 0 | 피지컬 컴퓨팅·"내 프로그램 만들기" 수업에서만 소재 |
| 성능 (C의 1/2) | 0 | 브라우저 인터프리터면 충분 |
| 한국어 오류 메시지 | 있음 | 이미 있음. 학습자용으로 다듬어야 함 |
| 점진 레벨·교안·LMS·브라우저 실행 | **없음** | 시장이 요구하는 것의 대부분 |

결론: 이 시장에 간다면 **"글 언어의 재사용"이 아니라 "글 문법을 가진 새 제품"**이다. 컴파일러는 남고, 제품은 처음부터다.

## 7. 검토했으나 근거를 못 찾은 가설

- **"AI가 쓰고 사람이 읽는 시대의 언어"** — 비개발자 검토자가 읽을 수 있는 코드. 논리는 그럴듯하나 찬성 증거 없음, LLM 무자원 문제가 정면으로 반대. 싸게 시험 가능: LLM에게 같은 명세로 글/파이썬을 쓰게 하고 정답률을 재면 된다 (미실행).
- **사무 자동화 (なでしこ의 실제 사용층)** — 국내는 노코드 RPA가 "한국어 최적화"를 내세워 채움. 비개발자의 포기 이유가 언어가 아니라는 후기가 반복됨. 인터뷰 없이는 판정 불가.

---

## 8. 결정 전에 할 실험 (1~2주, 비용 ≈ 0)

언어를 더 만들기 전에 **수요와 효과를 각각 하나씩** 확인한다.

1. **수요 — 정보교사 5명 인터뷰.** 질문 세 개: "엔트리 다음에 무엇을 쓰십니까?", "그때 무엇이 가장 막힙니까?", "한글 텍스트 언어가 있다면 쓰시겠습니까 — 왜/왜 아니오?" 마지막 질문에 "아니오"가 다수면 §0-1의 시장도 닫힌다.
2. **효과 — 독해 실험(종이).** 초6~중1 10~20명에게 같은 프로그램 셋(파이썬 / 엔트리 파이썬 / 글)을 보여주고 "무슨 일이 일어나는지" 말하게 한다. 정확도와 시간을 잰다. 글이 파이썬을 못 이기면 조사 어순의 차별점은 없는 것이다.
3. **경쟁 — 호랑 체험판 7일.** 문법을 직접 본다. 조사 기반이면 글의 차별점은 사라진다.

세 개 중 하나라도 부정이면 교육 시장은 접고, 글은 **"연구·예술 프로젝트"**로 정직하게 재정의한다 (11장 호환 약속은 그대로 유지). 셋 다 긍정이면 다음 문서는 "브라우저 글 인터프리터 + 레벨 설계"가 된다.
