# 방향 검토 — 지금 어디에 있고, 어디로 갈 것인가

작성 2026-09-04, 1.0.0-rc5 시점. 다음 단계를 정하기 위한 문서다. 현 상태는 측정했고, 방향은
근거와 함께 제안한다.

---

## 1. 현 상태

2세대는 48개 커밋으로 여기까지 왔다.

| 구성 | 규모 |
|---|---|
| 참조 구현 (파이썬) | 6546줄 / 19파일 |
| 자체 컴파일러 (글로 쓴 글 컴파일러) | 8872줄 / 13파일 |
| 표준 라이브러리 | 2743줄 / 14모듈 / 236함수 |
| 테스트 프로그램 | 4346줄 / 173개 |
| 문서 | 1263줄 / 8편 |
| 설계 결정 기록 | 46건 |

검증은 매 커밋마다 이만큼 돈다.

| 검증 | 결과 |
|---|---|
| 수용 테스트 (참조 / 자체 컴파일러) | 173/173 양쪽 |
| 덤프 교차 비교 (토큰·구문·IR) | 151개 입력 전부 일치 |
| 호출 색인 · 위험 보고 교차 비교 | 각 151개 일치 |
| 오류 메시지 (부정 테스트) | 49개 전부 같은 줄·열·문구 |
| 실행 파일 바이트 비교 | 128개 전부 동일 |
| 자기 컴파일 고정점 | 1·2·3세대 바이트 동일 |

언어에 있는 것: 묶음·합침·나열·별칭, 참조·배열·조각(`T[]`)·결과(`T 결과`), 제네릭(단형화),
가변 인자, 문자열 보간, 함수 값, 역할 조사에 의한 인자 대응, 동사형 호출과 괄호 호출.
컴파일러에 있는 것: 핍홀, 레지스터 할당(정수·실수), 작은 함수 인라인, 예외 진단, 호출 색인,
바꿔 쓰기 검사. 만들어진 실행 파일은 C 런타임 없이 kernel32 와 shell32 만 쓴다.

**언어와 컴파일러는 사실상 완성 단계다. 그 밖의 것은 아무것도 없다.**

| 있어야 하는데 없는 것 | 상태 |
|---|---|
| 입문서·배우는 길 | 없음. 명세 500줄이 유일한 자료다 |
| 편집기 지원 | 없음. 문법 강조조차 없다 |
| 다른 운영체제 | 없음. Windows x64 만 |
| 디버거 | 없음 (D-28 에 미룬 이유를 적었다) |
| 꾸러미 관리·생태계 | 없음 (D-15 로 이름공간도 없다) |

## 2. 글의 위치

### 2.1 비슷해 보이는 것들과 무엇이 다른가

모국어로 프로그래밍 언어를 만드는 시도는 흔하다. 대개 둘 중 하나다.

- **키워드 번역.** `if` 를 `만약` 으로 바꾼 것. 문법은 그대로이고 어순도 그대로다.
- **예술 프로젝트.** 문언(文言, wenyan-lang)처럼 고전 한문으로 쓰지만 자바스크립트로 옮겨 실행한다.

글은 둘 다 아니다. 두 가지가 다르다.

**문법이 의미를 진짜로 나른다.** 조사가 장식이 아니라 인자를 매개변수에 대응시키는 표지다.
`3을 "왼쪽"에서 "오른쪽"으로 옮기다` 와 `"오른쪽"으로 3을 "왼쪽"에서 옮기다` 는 같은 호출이다.
컴파일러가 격으로 대응시키기 때문이다. rc4 부터는 한 걸음 더 나아가, 같은 타입인 두 인자를
바꿔 쓸 수 있는 자리에서 조사를 안 붙이면 컴파일을 거부한다(D-30). 이것은 문법에 격이 있어야만
할 수 있는 검사다. 다른 언어는 인자에 이름을 붙이는 비용이 커서 위치 호출이 기본이고, 그래서
강제할 수 없다.

**네이티브로 컴파일하고 자기 자신을 컴파일한다.** 다른 언어로 옮기지 않는다. PE 를 직접 쓰고,
레지스터를 할당하고, 자기 자신을 컴파일한 결과가 세 세대 동안 바이트가 같다.

### 2.2 검증 방식 자체가 특징이다

참조 구현과 자체 구현을 나란히 두고 토큰·구문·IR·실행 파일 바이트까지 맞추는 방식은 취미
언어에서 보기 드물다. 이것은 "글로 쓴 컴파일러가 정말 같은 언어를 구현하는가" 를 매 커밋마다
기계로 확인한다. 이번 작업에서만 이 방식이 자체 구현의 버그를 세 번 잡았다 — 해제된 문자열을
가리키는 노드, 중첩 호출에서 새는 파서 상태, 자라는 배열을 넘겨 쓰는 인라인 맵이다.

### 2.3 그래서 누구를 위한 언어인가

정직하게 셋뿐이다.

1. **한국어로 프로그래밍을 배우려는 사람.** 영어 키워드를 모르는 상태에서 진짜 네이티브
   프로그램을 만들 수 있다. 글이 유일하게 대체 불가능한 자리다.
2. **언어 설계에 관심 있는 사람.** 격 체계를 인자 대응에 쓰고 그것을 강제하는 설계는 새롭다.
3. **만든 사람 자신.** 지금까지는 사실상 여기에 머물렀다.

시스템 프로그래머가 글로 갈아탈 이유는 없다. 그건 목표가 아니어야 한다.

## 3. 가장 큰 간극

**컴파일러는 완성에 가깝고, 두 번째 사람이 시작할 길은 없다.**

- 저장소의 README 는 프로젝트 상태 보고서다. "첫 프로그램" 이 없다.
- 배우려면 명세를 읽어야 한다. 명세는 구현자를 위한 문서다.
- 편집기에 붙여 넣으면 검은 글씨뿐이다. 문법 강조가 없다.

오류 메시지는 이미 좋다. 처음 하는 실수 여섯 가지를 시험해 봤다.

| 실수 | 나오는 말 |
|---|---|
| 마침표를 빠뜨림 | 문장 끝에 '.' 필요 — '반환' 앞에서 문장이 끝나야 합니다 |
| 영어 키워드를 씀 | 문장이 아닙니다 — 'return'(으)로 시작해서 '0'(으)로 끝납니다 |
| 세미콜론을 씀 | 알 수 없는 문자 ';' |
| 함수 대괄호를 빠뜨림 | 선언이 필요합니다 — '시작하기는'이(가) 있습니다 |
| 타입 없이 변수를 씀 | 선언되지 않은 이름입니다: 'x' |
| 빈 파일 | '시작하기' 함수가 없습니다 |

즉 **문 앞까지는 잘 만들어 놓고 문을 안 달았다.**

## 4. 세 갈래 방향

### 갈래 A — 사람이 쓸 수 있게 (입문·도구)

입문서를 쓰고, 편집기 지원을 만들고, 1.0 을 정식으로 낸다.

- **입문서.** 짧은 장 열댓 개, 각 장이 돌아가는 프로그램 하나. 마지막은 진짜 프로젝트 하나.
  중요한 것은 **문서의 모든 예제를 테스트로 만드는 것**이다. 이 프로젝트의 방식대로, 문서가
  낡으면 빌드가 깨지게 한다.
- **편집기 지원.** 문법 강조부터. TextMate 문법 파일 하나면 VS Code 확장이 된다. 비용은 작고
  첫인상에 미치는 영향은 크다. 언어 서버는 그다음이고, 호출 색인(D-24)이 이미 절반을 만들어 뒀다.
- **1.0 정식.** 명세를 얼리고 호환을 약속한다. rc 를 다섯 번 냈다.

비용은 몇 주. 대상은 위의 1번 사람. 글이 유일하게 대체 불가능한 자리를 실제로 채운다.

### 갈래 B — 언어 설계로서 밀기

격 체계를 더 밀고, 그것을 글로 남긴다.

- 역할 어휘를 넓힐지(지금 다섯), 역할로 이름을 대신할지, 같은 역할이 여럿일 때의 보호를
  어떻게 줄지 같은 미해결 문제가 있다. 07 문서의 한계가 그대로 연구 과제다.
- 이번에 얻은 측정치(호출의 0.1% 대 76%, 위험 121곳, 이전 비용)는 그 자체로 쓸 만한 자료다.

비용은 작고, 얻는 것은 이 프로젝트가 왜 흥미로운지에 대한 설명이다. 갈래 A 와 겹쳐서 할 수 있다.

### 갈래 C — 시스템 언어로서 넓히기

리눅스 ELF, 디버거용 예외 정보, 최적화 2단계.

지금 이것을 원하는 사람이 없다. 리눅스는 표준 라이브러리의 하부를 갈라야 해서 앞의 둘을 합친
것보다 크고, 예외 정보는 프롤로그 규약을 바꿔야 한다(D-28). 미룬다.

## 5. 제안

**갈래 A 를 하고, 갈래 B 를 문서로 곁들인다. 갈래 C 는 미룬다.**

근거는 이렇다. 컴파일러 쪽에서 남은 일은 전부 "있으면 좋은 것"이고, 최근 세 번의 최적화 시도가
모두 측정 앞에서 규모가 줄었다(D-29 의 121곳, D-31 의 기각된 세 통과). 반면 입문서와 편집기
지원은 없어서 겪는 손해가 100% 다. 아무도 시작할 수 없기 때문이다.

순서 제안:

1. **입문서** — 예제가 전부 테스트인 열댓 장. `build.py` 에 문서 예제 검증 단계를 더한다.
2. **문법 강조** — TextMate 문법 + VS Code 확장. 저장소 안에 둔다.
3. **1.0 정식** — 명세를 얼리고 호환 약속을 적는다.
4. (곁들여) **격 체계 정리** — 07 문서를 다듬어 이 언어의 기여가 무엇인지 한 편으로 만든다.

1.0 을 내기 전에 결정해야 할 것이 하나 남아 있다. 같은 역할이 여럿일 때의 보호다. 지금은
`[정수 a를 정수 b를 정수 c를 셋]` 같은 함수가 D-30 검사를 빠져나간다. 이것을 1.0 에서 어떻게
할지 — 그대로 둘지, 이름 붙인 역할을 도입할지 — 는 언어의 정체성에 닿는 문제이고, 정식 이후에는
바꾸기 어렵다.
