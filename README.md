# 글 (geul) 2세대

저장소: [github.com/wwoosshh/geul-lang](https://github.com/wwoosshh/geul-lang) 의 브랜치 `v2`. 1세대는 `main`에 있다. CI(`.github/workflows/ci.yml`)가 windows-latest 에서 수용 테스트, 자체호스팅 교차 검증, 글 컴파일러로 스위트 실행을 돈다.

한글 키워드와 한국어 어순(SOV)으로 프로그래밍하는 언어 **글**의 두 번째 설계입니다.
목표는 1세대와 같습니다. 과정이 다릅니다.

## 같은 목표

- 100% 한글 키워드. 조사(을/를/에/로…)가 인자의 역할을 정하고, 동사형(`쓰다` → `쓰기`)으로 함수를 부른다.
- C 컴파일러 없이 `.gl` → Windows `.exe`를 직접 만든다 (x86-64 PE 직접 생성).
- 컴파일러가 자기 자신을 컴파일한다 (자체호스팅).

## 다른 과정

1세대 감사(2026-09-03)에서 확인된 결함은 국소 버그가 아니라 네 가지 설계 결정에서 나왔습니다.
상태 의존 토큰화, 타입 없는 IR, 조용한 실패, 너무 이른 자체호스팅.
2세대는 이 넷을 설계 단계에서 뒤집습니다. 규칙은 [docs/00-헌장.md](docs/00-헌장.md)에 있습니다.

## 현재 상태

의미론(2026-09-03): 묶음은 값이며 대입·인자·반환이 복사다(D-16). 조각 `T[]`는 참조와 길이를 가진 값으로, 배열에서 암시 변환되고 `x[i:j]`로 잘라내며 색인마다 경계를 검사한다(D-17). 결과 `T 결과`는 오류 코드와 값을 가진 값으로, `오류(코드)`·`시도`·`혹은`으로 실패를 값으로 다룬다(D-18).
- 제네릭 (D-19): `묶음 목록(T)는 …`, `[목록(T) 참조 l에 T 값을 목록_추가(T)]는 …`. 호출은 인자에서 T 를 추론하거나 `이름(타입)(…)`으로 명시한다. 단형화 — 인스턴스는 처음 쓰인 순서로 만들어지고 이름은 `목록_추가(정수)`처럼 IR 덤프에 그대로 보인다. 표준 `일반목록.gl`의 `목록(T)`가 첫 사용처다.

**3단계(자체호스팅) 진행 중.** 설계 결정 D-01~D-11 확정(2026-09-03), 문법 명세 판 1, 수용 테스트 114개.
`ref/`의 Python 참조 컴파일러가 114개 전부를 통과합니다 (`python build.py test`).
표준 라이브러리 13개 모듈(기본·서식·문자열·입출력·수학·목록·배열·사전·바이트열·정렬·디렉터리·시간·체계)은 C 런타임 없이 kernel32 위에 글로만 쓰여 있고, 글로 쓴 컴파일러(`self/`)가 자기 자신을 컴파일해 바이트 동일한 실행 파일을 냅니다(고정점). 참조 구현과 토큰·AST·IR 덤프, exe 바이트가 모두 일치하고, 글 컴파일러로도 수용 테스트를 전부 통과합니다 (`python build.py selfhost`, `python build.py test --self`).

```
python build.py test            # 수용 테스트 전체
python build.py selfhost        # 자체호스팅 단계별 교차 검증
python ref/geulc.py 파일.gl     # 파일.exe 생성
python ref/geulc.py --check 파일.gl
```
요구사항: Python 3.12 (개발자만). 생성된 exe 는 msvcrt.dll·kernel32.dll·shell32.dll 만 쓴다.

## 진행 순서

1. **명세와 코퍼스** — 문법 명세 확정, 1세대 코퍼스를 명세에 맞게 고쳐 수용 테스트로 만든다. 코드 없음.
2. **참조 구현** — 명세를 그대로 구현하는 참조 컴파일러. 수용 테스트 전체 통과가 완료 조건.
3. **자체호스팅** — 언어가 컴파일러를 편하게 쓸 수 있을 만큼 성숙한 뒤. 참조 구현은 영구 부트스트랩으로 남긴다.

## 설치와 사용

배포물 `geul-<버전>-windows-x64.zip` 을 풀면 `geulc.exe` 와 `표준/` 이 나란히 있다. 그대로 쓴다.

```bash
geulc 안녕.gl
```

`안녕.exe` 가 만들어진다. `-o <출력.exe>` 로 이름을 정하고, `--version`·`--help` 가 있다. 표준 라이브러리는 실행 파일 옆의 `표준/` 에서 찾으며, `GEUL_ROOT` 환경변수로 다른 위치를 줄 수 있다. 만들어진 실행 파일은 Windows x64 에서 kernel32 만 필요로 한다.

배포물은 `python build.py release` 가 만든다: 참조 구현이 만든 `geulc` 로 다시 `geulc` 를 만들어 바이트가 같을 때만 묶는다.
