# 글 · 웹 행동 검토 실험

TypeScript·React 변경을 사람이 조건·결과·예외 단위로 읽는 표현을 연구한다. 현재는 부분 계산 엔진과 사례별 행동 검토 초안이 있으며, 앱 전체 행동 재구성·글→TypeScript 생성·사람 검토 개선은 아직 입증하지 않았다.

두 자료는 생성 후 볼 수 있다. 돌아가기 버튼은 부모 JSX 조건·속성 식과 자식 흐름을 연결하고, 조건 목록·변경 범위를 지정 입력의 계산 결과에서 생성한다. 메뉴 제한 제거·보기 모드 제한 복원·부모 속성 변경에 따라 설명도 다시 생성되는지 검사한다. 모바일 필터는 아직 사람이 구성한 조건 초안이다. 문서 2개와 전체 행동 검증 2개를 같은 성과로 세지 않는다.

## 실행

Node.js 22 이상과 Python 3.12를 사용한다. 원본·문맥·런타임 캐시를 준비하는 최초 절차는 기존 구현 기록의 실행 항목에 있다.

```powershell
cd web-review
npm.cmd ci --ignore-scripts
npm.cmd test
npm.cmd run verify:local -- --upstream
npm.cmd run prepare:behaviors
```

`--upstream`은 준비된 원본 앱 작업 사본을 사용한다. 원본 앱 검증 서버 56678·56680을 먼저 중지해야 한다. 전체 검증은 행동 자료도 생성한다. 별도 생성 명령은 자료를 다시 만들 때 사용한다. 기본 검증은 원본 앱 재실행을 생략하므로 기존 브라우저 기록의 대조와 혼동하지 않는다.

원본을 직접 탐색하려면 `python build.py web-review discover`, 변경 전후 후보는 `discover-change`, 후보 선택은 `lift-candidate`, 상세 읽기는 `read`, 유한 입력 비교는 `compare`를 사용한다. 비교 문서는 변경 범위 요약부터 읽고 상세에서 계산 구조를 확인한다.

## 다음 이정표와 동결 범위

1. 새 분석 모드를 추가하지 않는다. 먼저 위 두 사례에서 원래 고정한 기대 영향에 필요한 행동 연결의 공백을 확인하고 채운다.
2. 조건 목록·변경 범위·예외·미확인·원본 연결을 하나의 검토 흐름으로 만든다. 문법 지원 수와 검사 수를 진척 목표로 삼지 않는다.
   돌아가기의 입력 경계는 LayerUI 식의 스냅샷이다. 상위 앱의 설정 생성과 상태 전이는 미확인이다. 다음 연결 대상은 모바일 필터이며 사람 예행과 구분해 진행한다.
3. 기존 네 식 과제는 도구 예행용으로 유지한다. 세 사람의 표현 예행에서 이해 오류와 탐색 이유를 확인한 뒤 행동 단위 본 과제와 평가 기준을 고정한다.
4. 필요한 회귀 검사는 유지하되 새 모드를 위한 테스트 확장은 동결한다. 실제 검토 개선의 근거를 확보한 뒤 상태·비동기·TypeScript 생성 확장을 결정한다.
