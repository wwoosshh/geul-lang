# 예행 검토 화면의 설계

대상은 TypeScript·React 변경을 검토하는 개발자다. 화면의 일은 같은 원본과 입력 범위를 읽고 변경 조건·예외·보장 범위를 답하게 하는 것이다. 실제 참가자 모집·본 실험을 시작하는 화면은 아니다. 모든 내보내기에는 practice, participant=null을 기록한다.

화면을 홍보 대시보드로 구성하지 않고, 자료와 답안을 함께 펼친 작업대로 구성한다. 왼쪽에 선택한 조건의 자료와 원본 보기, 오른쪽에 답안과 경과 시간을 둔다. 핵심 장치는 원본 줄을 찾은 기록을 남기는 소스 여백이다. 자료와 소스를 전환해도 답안을 유지한다.

색은 작업지 `#f7f9fc`, 종이 `#ffffff`, 본문 `#1d293b`, 보조 글자 `#6b788b`, 강조 `#3357c8`, 강조 배경 `#e9effa`를 사용한다. 검토 내용이 중심이므로 배경 장식·그라데이션·성과 지표 카드를 두지 않는다. 제목은 로컬 명조 계열을 제한적으로, 본문은 맑은 고딕·Segoe UI, 코드와 시간은 Consolas 계열로 구분한다. 외부 폰트나 분석 서비스를 호출하지 않는다.

검토 자료는 기존 네 비교 조건의 내용을 구조화해서 표시한다. 원본·도메인·질문·용어 접근은 공통이다. B의 설명, C의 결정표, D의 구조 유지 한국어 풀이만 조건별로 달라진다. 별도 정답 파일과 채점표는 제공하지 않는다. 조건을 임의로 선택하는 기능은 예행 검토에만 적합하며 본 실험 배정으로 사용하지 않는다.

경과 시간에는 AI 대기와 다른 창에 있던 시간도 포함하고 각각 별도로 기록한다. 답변은 브라우저 메모리에 두고 사용자가 JSON 파일로 내보낸다. 서버는 localhost의 허용된 자료만 읽어 주며 답변을 받거나 외부로 전송하지 않는다. 모바일에서는 자료 다음 답안 순서로 쌓고 키보드 초점을 유지한다.
