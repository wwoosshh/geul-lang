# 웹 검토 표현 파일럿 초안

**방향 검토 후 보류:** 아래 네 식 과제는 도구·채점 절차를 점검하는 예행 자료로 유지한다. 행동 단위 표현의 효과를 검증하는 본 과제로 사용하지 않는다. 먼저 [두 행동의 표현 예행](behavior-rehearsal.md)을 수행하고, 그 결과로 본 과제와 평가 기준을 다시 고정한다. 기존 과제의 결과로 연구 방향의 효용을 판정하지 않는다.

상태: **참가자 0명, 실험 미실시.** 2026-09-09. 이 파일은 모집 전의 설계 초안이다. 분석 성공률이나 사람 검토 개선을 보고하는 결과물이 아니다. 현재 네 부분 과제에 실행 근거가 있으며, 12개 전체 행동 과제는 아직 준비되지 않았다.

## 검증할 질문

실행 근거와 원본 위치를 갖는 글의 표시가 같은 자료와 AI를 사용하는 개발자의 변경 영향 판단에 도움을 주는가? 한국어라는 사실, 결정표라는 표현, 실행 흔적이라는 정보의 효과를 구분한다. 새 언어 패러다임이라는 주장은 이 파일럿만으로 확정하지 않는다.

첫 파일럿은 6~8명의 한국어 사용자 중 TypeScript·React 코드 검토 경험이 있는 개발자를 목표로 한다. 이미 프로젝트 내용을 아는 개발자와 처음 보는 개발자를 기록하고, 언어 제작자는 독립 참가자 수에 넣지 않는다. AI 에이전트 응답은 참가자 응답으로 사용하지 않는다. 아직 인터뷰나 모집 연락을 보내지 않았다.

## 네 비교 조건

| 조건 | 제공하는 것 |
|---|---|
| A | 고정된 원본·diff·프로젝트 문맥 + AI |
| B | A + 글의 실행 설명·변경 조건·원본 연결 |
| C | A + 같은 입력 도메인·관찰 결과의 결정표 |
| D | A + 원본의 식별자·연산자에 한국어 풀이를 붙인 구조 유지 표현 |

네 조건에 동일한 원본 접근권과 같은 AI 모델·도구·시간 제한을 준다. B만 원본 위치에 접근할 수 있도록 제한하지 않는다. C의 결정표에서 반례나 미지원 표시를 빼서 B를 유리하게 만들지 않는다. D에 제공할 용어 대응은 B에서도 동일하게 쓴다. 용어 대응은 실행 의미와 별도로 기록한다.

참가자 간 조건 순서를 회전하고, 같은 참가자에게 같은 변경을 다른 표현으로 반복 제시하지 않는다. 과제별 조건 배정도 회전한다. `prepare:pilot`은 네 독립 변경의 16개 자료와 미배정 슬롯 8개를 만든다. 8개 슬롯에서 과제×조건, 과제×순서의 각 조합이 두 번씩 나오도록 검사한다. 조건의 인접 순서도 회전한다. 이는 참가자 8명이 실제 실험에 참여했다는 뜻이 아니다. 6명에서 종료하면 완전한 8슬롯 균형이 충족됐다고 하지 않는다. **사람 예행 검토와 최종 채점표를 마치기 전에는 본 파일럿을 시작하지 않는다.** 최종 실험 파일을 잠근 다음 참가자를 시작한다.

## 과제의 범위와 정답

현재 `tasks.json`의 과제는 원본의 특정 계산 지점에 도달했고, 표시한 입력 도메인을 충족한다는 전제다. 전체 앱 사용 흐름을 예측하는 과제가 아니다. 이 전제를 모든 조건에 똑같이 설명한다.

각 과제는 다음을 묻는다.

1. 어느 입력 조건에서 관찰 값이 바뀌는가?
2. 그때 변경 전후 값은 각각 무엇인가?
3. 비슷해 보여도 바뀌지 않는 예외 한 가지는 무엇인가?
4. 이 결과로 실제 화면 표시·사용 가능성 또는 서버 동작까지 결론 낼 수 있는가?
5. 자신의 답에 얼마나 확신하는가? 추가로 확인할 원본이나 실행은 무엇인가?

실행 결과와 독립적으로 작성한 기대 조건의 일치가 확인된 과제만 제출용으로 사용한다. 현재 자동 검사 파일은 `corpus/slices.json`, `scripts/check-corpus.mjs`다. 참가자에게 정답 파일·채점 규칙 자체를 공개하지 않는다. 다만 실제 검토 도구가 제공하는 변경 설명을 숨겨서 제품의 정보를 인위적으로 줄이지도 않는다.

정답 채점은 표현 종류를 가린 응답으로 수행한다. 조건·전후 값·예외·보장 범위 각 항목을 별도로 채점한다. 보장 범위 밖에 대해 단정한 답과 높은 확신을 함께 기록한다. 복수 채점자가 준비되지 않은 경우 단일 채점자라는 한계를 남기고 신뢰도가 측정됐다고 하지 않는다.

[채점 초안과 예행 도구](SCORING.md)를 추가했다. 네 항목의 0·1·2점 기준은 `rubric.json`에 있으며 사람이 최종 검토해야 한다. 도구는 조건 메타데이터를 가린 양식과 원본 기록을 분리하고, 미채점 항목을 0점으로 바꾸지 않으며, 사람이 입력한 점수의 합계만 확인한다. 자유 서술의 정답 판정과 실제 사람 평가를 자동화한 것으로 취급하지 않는다.

## 기록과 판단

기록할 원자료는 익명 참가자 코드, 경험, 과제·조건·순서, 시작/완료 시각, 원본 이동 횟수, AI 사용 횟수와 모델 버전, 응답·확신도, 항목별 점수, 중단 이유다. 개인정보나 실제 비공개 서비스 코드는 필요하지 않다. 본 자료를 연구 공개물로 공유하려면 참가자에게 그 사용 범위를 설명하고 동의를 받아야 한다.

검토 정확도를 우선 보고하고 전체 응답 시간, 정확히 푼 과제의 시간, 원본 이동, 잘못된 확신을 함께 보고한다. 정확한 답만 골라 빠르다고 주장하거나, 시간 초과·미완료 응답을 제거해 성능을 높이지 않는다. AI 대기 시간을 포함한 시간과 별도 기록한 대기 시간을 모두 남긴다. 같은 참가자의 반복 응답을 독립된 참가자로 세지 않는다.

6~8명의 파일럿은 사용성 문제와 효과의 방향을 살피는 단계다. 작은 차이가 불명확하면 효과가 없다는 확정으로 바꾸지 않는다. 원본 대비 50%, 원본+AI 대비 25% 시간 절감이라는 기존 장기 목표를 파일럿이 이미 충족했다고 보고하지 않는다. 더 큰 실험의 표본 수와 판단 기준은 파일럿 관찰을 바탕으로 별도 설계한다.

다음 상황에서는 상태·비동기 기능 확대보다 현재 표현과 분석 단위를 먼저 고친다.

- 중요한 조건을 오해하거나 범위 밖 보장을 더 자주 믿는다.
- B를 읽어도 같은 원본 탐색을 다시 해야 한다.
- 같은 정보의 결정표 C보다 검토에 도움이 되지 않는다.
- 원본+AI 조건과 비교한 장점이 불분명하고, B의 추가 정보가 실제 검토 결정에 쓰이지 않는다.

## 시작 전 남은 일

- 준비한 네 부분 과제의 질문·정답 범위를 사람이 점검하고, 전체 행동 검토 과제와 구분한다.
- 생성한 네 조건 자료의 정보·용어·AI 접근과 원본 링크를 사람이 점검한다.
- 배정표·채점표·중단 처리·시간 측정 방식을 실제 사람이 읽고 예행 검토한다.
- 실제 참가자를 확보한다. 현재 사용자에게 시험 가능한 집단은 없다고 확인된 상태다.

[예행 검토 화면](viewer/README.md)을 추가했다. 네 조건 자료, 원본 줄 이동, 시간과 답변 JSON 기록을 점검할 수 있다. 실제 참가자 배정은 적용하지 않으며 모든 응답을 practice-only로 표시한다. 자료가 시작 전에 보이므로 본 실험의 검토 시간으로 사용하지 않는다. 내장 브라우저 파일 다운로드의 한계와 JSON 복사 대안도 기록했다.

위 작업을 마치기 전의 자동화 점검은 실험 도구의 검사일 뿐 사람 평가 결과가 아니다.
