# 거래 선택 검토 작업대

Actual의 `actual-mobile-report-filter` 한 사례를 사용하는 로컬 연구 시연이다. 기존 예행 검토의 4개 과제·대조 조건은 변경하지 않는다. 사용자는 고정된 160개 입력 조합 중 하나를 선택하고 목록 관찰의 전후 차이, 계산 구조, 원본 참조를 살펴본다. 브라우저에서 Actual 코드를 실행하거나 실제 사용자·서버 상태를 만들어 내지 않는다.

```powershell
cd web-review
npm.cmd run verify:local -- --upstream
npm.cmd run inspector
```

주소는 `http://127.0.0.1:56679`다. 기존 분석 결과가 이미 현재 엔진으로 준비됐으면 `npm.cmd run prepare:inspector`만 다시 실행할 수 있다. `test:arrays` 이후 `test:array-traces`, `test:arrays`와 `test:jsx-properties` 이후 `test:slice-scope`, `test:props` 이후 `test:output-props`의 현재 결과가 필요하다. 전체 검증 명령은 선후 관계를 지킨다.

상단은 선택식 결과다. 색으로 표시하는 위치는 전체 관찰값·순서의 차이에서 얻으며 ID가 같다는 이유로 객체를 같은 것으로 판단하지 않는다. ‘변경’은 조건 구조 변화와 유한 입력의 범위를, ‘구조’는 가능한 분기 구조를, ‘계산’은 지금 고른 입력의 IR 기록을, ‘사용처’는 부모·자식 소스 연결을 보여준다. 원본 위치를 누르면 같은 버전의 실제 소스와 해당 범위를 강조한다. 좁은 화면에서는 원본으로 이동하며, ‘읽던 설명으로 돌아가기’로 누른 위치와 키보드 초점을 되찾는다.

‘계산’에서는 전후 버전을 바꾸며 실제로 선택한 IR 분기, 원소별 남김·제외, 이어 붙이는 순서를 따라 읽는다. 기록은 원시 값 읽기 등 모든 연산을 남기지 않으며, 객체와 긴 문자열의 값 미리보기는 전체 값이 아니다. 단락 연산의 오른쪽에 진입했다는 기록도 그 계산의 정상 완료를 보증하지 않는다. 별도 오류·미지원·기록 상한 상태를 구분하며, 현재 고정 예시 160쌍은 생성 시 모두 정상 결과와 기록 상한 미도달을 확인한다.

하단 ‘정상 목록 밖의 입력’은 기존 배열 검사의 별도 경계 입력 12쌍을 보여준다. null·undefined 거래 원소 또는 null 미리보기 목록과 검색·필터의 네 조합이다. 전후 24개 결과 중 TypeError는 9개이며, 검색이 꺼지고 필터가 켜진 3쌍에서 오류가 목록 반환으로 바뀐다. 반환한 `[null]`이나 `[undefined]`가 자식에서도 안전하다는 주장은 하지 않는다. 실제 앱이 이 입력을 만들 수 있는지도 미확인이다. 위 160쌍의 입력·결과는 이 선택기로 바뀌지 않는다.

경계 입력의 81개 IR 기록 중 공통 계측 대상 36개에만 대조 표식을 붙인다. TypeError 이름의 일치와 IR의 오류 위치는 구분하며 오류 위치에는 원본 계측 표식을 붙이지 않는다. 입력 그룹·키·버전·값을 맞춰 근거를 결합하므로 정상 입력의 대조 기록을 예외에 재사용하지 않는다. 화면 아래에서 원본 링크를 눌렀을 때 원본 패널이 보이지 않으면 데스크톱에서도 해당 위치로 이동하고, 복귀 버튼으로 읽던 위치와 초점을 되찾는다.

이 입력·버전의 원본 계측 기록과 값·순서·원본 위치가 일치한 조건·필터 판단·완료 길이에는 ‘원본 계측과 대조한 기록’을 표시한다. 다른 입력·버전·결과의 근거를 붙이면 거부한다. 저장·복사 세부 단계는 같은 표시를 받지 않으며 ‘원본 대조 범위’에서 확인할 수 있다. 계측 전 원본과 계측본의 결과도 별도 비교하지만, 원본 앱의 상태·hook·DOM을 실행한 증거가 되지는 않는다.

‘구조’ 아래의 ‘입력이 선언된 곳’은 입력 이름의 선언·구조 분해 패턴·원래 초기화 식으로 이어진다. 거래 목록의 `useTransactions` 등 hook 호출이 소스에 적힌 사실을 보여주며, 그 hook을 실행하거나 현재 예시와 같은 반환값을 만들었다고 판단하지 않는다. 원본에 나타나는 조건부 기본값과 선언 전체의 초기화 식도 구분한다.

‘원본 변경에서 선택한 구간과 선택 밖 변경’에서는 Git의 삭제·추가 줄과 선택식 원본 구간의 교차를 보여준다. 변경 전 삭제 12줄 중 4줄, 변경 후 추가 56줄 중 5줄이 선택과 겹친다. 선택 밖 변경 줄은 연속 구간으로 묶어 같은 버전의 원본에 연결한다. 이 수치는 텍스트의 교차이며 동작 해석 성공률이 아니다. 선택 밖이라는 표시는 미지원이나 영향 없음이라는 판정도 아니다. 줄 끝 개행은 소스 위치의 끝에 포함되지만 다음 줄까지 강조하지 않는다.

자료 생성은 원본 diff의 삭제·추가·문맥·변경 사이 구간과 마지막 개행을 확인하고 변경 후 파일을 재구성한다. 선택 구간은 원본에서 다시 만든 IR의 범위·해시와 맞춰 확인한다. 범위·줄 수·diff가 다른 결과를 원본에 붙이지 않는다. 이는 원본 텍스트의 일치 검사이며 새 앱 실행 증거가 아니다. 변경 줄 파서와 범위 생성 도구도 작업대 자료의 의존 해시에 포함한다.

준비 스크립트는 현재 프로듀서·원본·도메인·IR의 해시를 확인하고 CLI로 양쪽 읽기와 비교를 재검사한다. 브라우저가 선택할 전후 관찰·기록 160쌍을 계산해 이미 원본 대조한 비교 결과와 맞춘다. 이 준비 과정의 원본 앱 실행 횟수는 0이다. 이 시연이 브라우저에서 원본 앱의 동작을 검증했다는 뜻은 아니다.

`build/web-inspector/`의 자료와 화면 자산·계측 도구 해시를 결합한다. 소스·화면 자산·계측 도구가 달라지면 해당 근거와 자료를 재생성하고 서버를 재시작한 후 브라우저를 새로고침해야 한다. 서버는 localhost의 고정된 GET·HEAD 경로만 제공한다. 임의 파일 경로로 조회하는 API는 없다. 이런 일관성 검사를 외부 서명이나 출처 인증으로 취급하지 않는다.

UI 확인은 설명의 표시·입력 연결·원본 이동·배치를 대상으로 한다. 사용자 검토 성과, 접근성 도구 전체의 동작, 실제 앱의 화면·상태·요청을 대신 검증하지 않는다. 전체 행동 0/12, 참가자 0명 상태는 유지한다.

`browser-evidence/`는 당시 자산·자료에 대한 보존 기록이다. 이후 파일이 바뀌면 현재 UI 검증으로 취급하지 않으며 전체 검증 명령이 이 브라우저 조작을 재실행하지 않는다.
