# 거래 선택 검토 작업대

대상은 Actual의 고정된 거래 선택 변경 한 건을 살펴보는 개발자다. 화면의 한 가지 일은 입력 예시를 바꾸면서 선택식의 전후 결과, 가능한 계산 구조, 원본 위치를 함께 읽게 하는 것이다. 기존 사람 평가 4개 과제와 조건은 교체하지 않는다. 사용자 실험과 전체 앱 동작의 완료 지표는 계속 별개다.

색은 종이 바탕 `#F2F7F6`, 흰 작업면 `#FFFFFF`, 본문 `#182F33`, 계산·선택 강조 `#157F76`, 원본 탐색 `#5852A6`, 제거·변경 전 강조 `#AD3752`로 제한한다. 글자 역할은 작은 ‘글’ 표식에 궁서/Gungsuh, 본문과 제목에 맑은 고딕, 소스·값에 Consolas를 쓴다. 외부 글꼴·이미지·분석 서비스는 사용하지 않는다.

구조는 결과를 상단에, 설명과 원본을 나란히 놓는 작업면이다. 긴 설명을 한 줄 요약으로 숨기기보다는 계산 분기를 접고 펼치며 원본 위치로 이동한다. 기억할 요소는 바뀐 조건식의 위아래 짝이다. ‘변경 전/후’ 조건 문장을 누르면 해당 원본 위치를 직접 비춘다. 결과 ID의 색은 독립적으로 재구성한 목록 차이의 위치를 따르며 ID를 객체 동일성으로 취급하지 않는다.

```text
글 검토 작업대 / Actual 거래 선택                         부분 분석
필터를 켰을 때, 어떤 거래가 남을까
[검색] [필터] [거래 예시] [미리보기 예시]
선택식 결과: 변경 전 목록 → 변경 후 목록      [전체 값 보기]
┌ 읽는 내용: 변경 / 구조 / 계산 / 사용처 ┬ 원본: 전후·파일 선택 ┐
│ 변경 조건, 구조, 계산, 사용 위치  │ 선택한 줄과 주변 소스 │
└──────────────────────────────────┴──────────────────────┘
검사한 범위·미확인 범위·고정된 근거
```

기존 예행 검토 화면의 서체·표 위주 배치를 반복하는 안은 제외했다. 입력 예시를 바로 바꾸고 결과와 해당 근거를 같은 화면에서 확인하는 흐름을 먼저 둔다. 숫자 대시보드, 장식용 단계 번호, 실행 성공으로 오해할 수 있는 녹색 완료 표시는 쓰지 않는다.

자료는 기존 원본·IR·프로듀서 해시를 재검사한 뒤 생성한다. 브라우저에서는 미리 계산한 160개 스냅샷만 선택한다. 실제 Actual 앱이나 네트워크·hook·자식 렌더러를 실행하지 않는다. 원본 링크와 값은 텍스트로 삽입하고 서버는 고정된 자산·자료만 localhost에 제공한다. 키보드 조작·명시적 선택 상태·모바일 한 열 배치·오류 안내를 확인한다.

구조와 선택한 입력의 기록은 각각 ‘구조’와 ‘계산’으로 구분한다. 계산 기록은 원래 발생 순서를 보존하고 연산 원본·판단 조건으로 연결한다. 문장을 한 줄 요약으로 압축해 생략한 연산을 실행한 것처럼 꾸미지 않는다. 좁은 화면의 원본 이동에는 읽던 설명으로 돌아오는 버튼과 초점 복귀를 제공한다.
